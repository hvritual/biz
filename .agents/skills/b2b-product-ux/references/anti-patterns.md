# B2B UX 反例检查

用于设计分析和独立评审。不是当前产品缺陷断言，不是自动评分器。严重问题不能被其他维度平均分抵消。

| 反例 | 漏洞 | 替代设计 | 证明方式 |
|---|---|---|---|
| 每页巨大指标卡+万能表格 | 任务和决策没有主次 | 按任务选页面及必要模式 | 用户能定位首要事实与下一动作 |
| 所有页面强制分页和多级筛选 | 小集合徒增成本 | 依据集合规模和真实查询协议选择 | 查询/返回任务测试 |
| 查看详情即勾选对象 | 批量范围被意外改变 | 查看、选择分离 | 浏览器保留选择集合 |
| 关闭详情重置列表 | 用户反复恢复上下文 | 保留条件、页码、滚动、焦点 | 打开/关闭/返回测试 |
| 跨租户保留旧草稿与已选设备 | 泄露数据或误操作 | 按身份清理并重新读取 | 身份切换负例 |
| 离线显示停机和损失金额 | 用推测代替事实 | 标明最后报告时间、未知和核实动作 | 数据来源与现场确认 |
| 缺价格/额度/指标时显示0 | 错误暗示免费或可用 | 明示未知/未提供 | 缺字段与错误态测试 |
| 危险后果只在tooltip | 键盘/触屏用户看不到 | 常驻影响与必要确认 | 键盘、触屏、缩放与理解测试 |
| 每次筛选都弹确认 | 低风险操作被过度打断 | 按风险调整提示强度 | 熟练用户任务观察 |
| 保存成功等同生效 | 异步受理被冒充完成 | 回执、进度、权威回读 | 真实API/部分成功/超时测试 |
| 超时自动换ID重试 | 可能重复副作用 | 查原状态，遵守幂等协议 | 网络故障及重放负例 |
| 自助引导含编造维修步骤 | 设备安全与有效性无依据 | 有审核资料才指导，否则接管 | 机型/版本/来源审核 |
| 工单创建就关闭业务问题 | 用户结果未完成 | 分离交接与业务解决条件 | 端到端处理与现场结果 |
| 新建SmartTable/Props副本 | 第二权威、后续漂移 | 源码索引+实际组件组合 | 路径、来源摘要和diff检查 |
| 截图漂亮即证明人性化 | 未证明理解/效率/恢复 | 九维逐项标验证范围 | 浏览器、API、真人证据分栏 |
| 模板填true即通过 | 没有候选/结果/来源绑定 | 按现有UX Contract核对证据 | 失败/旧SHA/错误范围反例 |

反例被触发时记录对象、任务、实际证据、影响和最小修正。没有证据写“待验证”，不能仅凭概念判断现有页面一定有错。对应 [模式库](b2b-interaction-patterns.md) 与 [指导规则](guidance-and-recovery.md) 选择改法。
