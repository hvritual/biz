# 任务推进：先保全目标，再推进有证据的下一步

关联 #332；来源为 #331 模块管理旅程交付的复盘与用户明确要求。这里沉淀执行方法，不重新判定历史产品验收，也不修复 #331 的业务代码。

## 触发、边界与读取

每次开始仓库任务、收到“下一步／继续／result”、恢复上下文、移交执行者、进入下一阶段、准备提交/交付时，执行本 Skill 的相关检查。不是每条闲聊都运行完整流程；只读分析不因此获得写权限。

先读根 [AGENTS.md](../../../AGENTS.md)、当前任务/Issue 原文、已确认范围与最近有效 checkpoint，再回读本轮实际 branch/base/head、PR 和相关执行证据。历史摘要、截图、旧 green run 和本 Skill 内的文字不能代替当前来源。

业务设计继续加载 [B2B Product UX](../b2b-product-ux/SKILL.md) 与其 [证据边界](../b2b-product-ux/CHECKING.md)；UI 继续使用 [UI 交付链](../../../docs/UI-DELIVERY-CHAIN.md)、当前 CoffeeLink 规范及 typography。不创建第二份 Page Contract、权限目录、状态机或业务规则。

使用 [checkpoint 模板](templates/checkpoint.md) 的适用部分更新当前任务已经授权的文档/Issue。优先引用现有任务基线和验收条目，不为每次点击或思考生成一份新文档。模板是交接记录，不是机器协议，不覆盖 `docs/commercial-entitlements/tasks.json` 或其他既有任务状态权威。

## 风险分类：按行为，不按文件位置

| 分类 | 最小检查重点 |
|---|---|
| T0 工程/文档 | 范围、来源、结构/链接、行为保持、相关工程回归 |
| T1 展示 | 现有组件/Token、视觉、适用视口、可访问性 |
| T2 交互 | 上下文、选择/筛选状态、焦点、键盘、退出与恢复 |
| T3 后台能力 | 授权、租户、业务不变量、版本/并发、错误与可观测性 |
| T4 用户业务任务 | Actor → Object → Understand → Action → Result → Recovery 的完整任务证据 |

涉及权限、租户隔离、资金、额度、删除、远程设备、外部或异步副作用，不得因为只改一个 Vue 文件就降低检查；用户直接触发时按 T4。纯分析、文档或只改间距不强制运行业务 E2E。风险不明先核实，不用 N/A 掩盖未知。

## 每个阶段怎样推进

以下是现有工作流的检查点，不新增调度状态或阶段编号。按任务类型记录适用性及理由；分支流程不强行串成线性旅程。

| 阶段 | 进入时读取什么 | 必须留下什么 | 何时不得推进受影响工作 |
|---|---|---|---|
| 启动/恢复 | 用户原文、既有目标/范围批准、最近 checkpoint、实时源码与任务状态 | 原始必做任务引用、当前切片、候选信息、前轮未决项、唯一下一动作 | 目标不明、范围已漂移、上下文/证据无法确认 |
| 需求与任务基线 | 用户要达成的结果、业务生命周期、T0–T4 分类 | 任务稳定 ID、预期可观察效果、非目标、验收场景；关键歧义的确认记录 | 将“管理/关联/核验”等歧义擅自解释成最容易实现的只读页 |
| 能力与契约核对 | 当前 Operation、实现、实际消费者、路由/按钮、批准规格 | 双向覆盖表与逐操作行为依据；已有能力未接入和真实缺口分别记录 | 未查实现就说无接口；业务语义依赖猜测；规格与实现冲突未决 |
| 设计与实施计划 | 已冻结任务与事实、已有组件、依赖和允许修改范围 | 每个任务的入口/操作/结果/失败恢复、测试预期、文件边界与有界切片 | 用只读或占位提示替代必做变更；缺后端时静默删任务 |
| 实施 | 批准切片、当前契约与预先定义的验收 | 最小改动、实际调用、状态/恢复处理、运行记录与差量 | 改验收让代码过关；超出权限/文件边界；已发现契约冲突仍沿用错误假设 |
| 验证与评审 | 独立读取的候选/环境/真实结果，原始必做任务 | 逐任务通过/失败/未验证证据；API/Mock/浏览器/真人审阅分栏 | 缺结果回读；只有截图/结构检查；跳过任务被算完成；旧证据冒充新候选 |
| 提交与交付 | 实际 diff、当前 PR/base/head/run attempt、独立批准 | 明确区分代码已提交、候选验证、合并、main 回读、部署/业务验收 | 未获授权合并/部署；候选已变化；全绿但必做任务仍未完成 |
| 复盘与交接 | 原始目标差异、失败证据、有效修复、未决事项 | 更新反例/规则/模板的具体位置；继承全部未完成任务的 checkpoint | 只写“以后注意”；把经验写入当作自动检查已部署 |

阻断受影响的任务或阶段，不无期限空等。列出缺口、责任/依赖、可恢复条件和下一动作；可以继续无依赖且已获授权的切片，但整体保持部分完成。无须修改时报告已有证据，不为“执行”制造无意义 diff。

## 任务范围不可静默缩减

1. 任务基线来源于用户目标，不从旧页面按钮或已写代码反向生成。不是机械要求所有对象具备 CRUD；不适用必须有业务理由。
2. 区分 read（查看已有关系）、manage（改变权威定义）、grant（给角色/成员授权）、verify（核验实际可用性）。名称类似不代表交付效果相同。
3. 复用现有布局/组件，不等于限制为已有功能；“只改前端”是文件边界，不是任务完整性豁免。缺少必要后端修改授权时记录依赖并申请范围决策。
4. 变更必做任务、写降只读、改变权威来源、安全边界或验收标准，必须保留旧要求、变更理由、影响及真实批准引用。实施者自己的 `approved: true` 不构成批准。
5. 实现方法、样式和文件拆分在授权范围内自行推进；关键范围变化才请求用户决策，不用频繁确认阻塞正常工作。
6. 阻塞、跳过、未接入保留在原任务集合。分阶段交付报告原始总任务、批准后的当前范围和切片结果；未批准时不得减小完成率分母。

## 双向覆盖与行为依据

检查：用户任务 → Operation/能力 → 实现 → 前端动作（适用时）→ 结果/恢复；反向检查本次相关的已有能力是否遗漏、设计按钮是否有真实依据。后台任务/内部操作可以没有页面，须标明理由。前端封装缺失不等于后端不存在。

每个写操作单独记录：前置权限/租户/对象条件、直接效果、连带状态变化、哪个版本何时变化、回执语义、权威回读、幂等与并发、超时/部分结果/恢复。引用精确源码/契约/测试位置及候选；不另手写一份业务状态机。

不得预设所有写操作都 version+1，也不得预设技术与销售分别管理就绝无联动。请求已接收、已执行、后续状态被他人修改、结果未知应按真实契约区分。回读版本不等于回执版本，不自动等于执行失败。

批准规格、当前实现和测试不一致时标明冲突与需要的决策；代码现实不是产品批准，历史规范也不能掩盖当前行为。不能为了方便选择 Mock 作为真相。

## 验收先定义，证据独立读取

- 每个必做任务先定义 Given/When/Then、初始条件、权威效果与失败路径，再实现。新增从“记录不存在”开始；建立关联从“关系不存在/需改变”开始。只读任务有只读验收，不套写操作要求。
- Mock 用于组件与边界测试，其行为必须对照服务实现/独立契约测试。生成类型相同不证明版本、状态联动、权限或幂等行为相同。
- 关键业务场景使用隔离测试条件下的真实业务逻辑。外部替身、fixture、真实服务、浏览器、用户测量与人工审阅分别标注；没有运行环境写未验证，不访问生产数据补测。
- 预期结果、范围基线和业务断言不能与实现一起被静默删改；改变判定标准需独立复核。换一个模型但共用同一个错误 Mock，不等于独立验证。
- 任务证据绑定外部回读的候选/相关源码、基线版本、环境、命令、run attempt、结果和范围。代码、契约、任务或测试判定变化后，相关证据必须复核/重跑；旧失败保留并记录修复与复测关系。
- 不做自引用哈希证明：文档自己填入的 candidate/hash/reviewer 不独立认证该文档。无候选时明确无候选，不伪造 SHA。
- 视觉证据同时检查操作前后目标状态确实可见；截图张数/分辨率、通过测试数量、构建成功均不代替任务闭环覆盖。
- 复用既有六项 Task Contract、Page Contract、B2B UX 与候选/main 规则；业务任务缺一项关键结果或恢复，不用平均分抵消。

## 阶段结束/交接的最小报告

按 [模板](templates/checkpoint.md) 记录：目标与范围是否变化；本轮实际完成；逐任务覆盖与阻塞；当前候选及有效证据；未运行/待决策项；一个下一动作及条件。面向用户的简报引用同一记录，不维护另一份状态。

“继续/下一步”继承原目标、全部未完项、已有禁区与批准记录，不代表新授权合并/部署；按授权推进而不是重新缩小目标。读取失败先说明缺失，不能凭上一轮口头“已完成”跳过检查。

## 规则、机器检查和批准分开

本 Skill 与根入口是 Agent 执行约束；模板是记录工具。它们不自动阻止 GitHub 合并，不运行工作流，不修改状态台账，不批准产品完成，不安装全局记忆。

既有 `make b2b-ux-skill-check` 只具有 [CHECKING.md](../b2b-product-ux/CHECKING.md) 所述结构与证据边界，不能宣传它已识别所有语义降级。本 Skill 未增加确定性范围/状态语义检查器，也未修改 CI 路由或 allowlist。

按变更实际运行根 AGENTS 要求的命令及现有检查，不执行模板中的占位命令。缺依赖、未运行、仅离线结构通过、人工待审分别报告。PR 资格与 main 验证维持原规则，不能为了文档 PR 通过而降低门禁。

[反例清单](references/prevention-cases.md) 指明后续检查器应捕获的故障；清单存在不等于测试已经实现。将规则转成自动检查需另有明确实现、执行结果和反例失败证据。
