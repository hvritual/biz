# 02 实施路线与并行安排

## 1. 拆解原则

路线按可交付业务能力划分，不按“所有数据库→所有接口→所有页面”串行堆叠。每个 CE 任务必须独立构建、验证和提交；允许依赖已合并的前置契约，但不能依赖另一个任务的未提交工作区。

`tasks.json` 的 `depends_on` 是唯一硬依赖事实源；路线文件中的 `依赖` 行用于阅读并由检查器交叉校验。跨路线不是整体互锁，例如套餐目录 CE-07 不必等 R2 全部完成，前端基线 CE-11 不必等订阅接口。

## 2. 与上一轮 M01～M07 的对应

| 原方案 | 本次任务范围 |
|---|---|
| M01 模块目录与映射 | R1：CE-01～CE-03 |
| M02 生效权益与后端限制 | R2：CE-04～CE-06 |
| M03 套餐版本与订阅 | R3：CE-07～CE-10 |
| M04 可信会话与 Vue 接入 | R4：CE-11～CE-14 |
| M05 自动变更闭环 | R5：CE-15～CE-17 |
| M06 额度与字段纵向闭环 | R6：CE-18～CE-20 |
| M07 生产化与扩展 | R7：CE-21～CE-23；R8：CE-24～CE-26 |

CE 命名空间仅属于本商业权益计划，不复用现有 YU、AG、B12 等任务编号。

## 4. 推荐执行波次

波次是协作安排，不是额外依赖，不给出未经团队容量验证的工期承诺。

| 波次 | 推荐任务 | 退出结果 |
|---|---|---|
| W0 | CE-01 | 锁定来源、生成与事务扩展点、共同契约、测试证据约定 |
| W1 | CE-02；并行 CE-11、CE-12 | 能力目录可用；前端来源与真实身份路径闭合 |
| W2 | CE-03、CE-04、CE-07 | 技术映射、专项授权切片、套餐版本可分别验收 |
| W3 | CE-05、CE-08 | API 权益门禁与默认订阅初始化 |
| W4 | CE-06 | 版本／失效／并发撤权语义锁定；开放下游消费 |
| W5 | CE-09、CE-14、CE-18、CE-20 | 订阅切换、租户呈现、额度核心、字段保护可独立推进 |
| W6 | CE-10、CE-13、CE-19；条件满足可做 CE-21 | 开通任务、平台配置、真实额度接入；形成 MVP |
| W7 | CE-15、CE-16；并行补齐 CE-21 | 自助切换和自动到期；附加包完成 |
| W8 | CE-17；条件满足执行 CE-22／CE-23；可启动 CE-24 | 故障恢复；外部能力按条件接入；存量迁移演练 |
| W9 | CE-25；完成 CE-24 | 全链路压力与迁移报告 |
| W10 | CE-26 | 分批启用、回滚演练和最终版本回读 |

一个人执行时按相同依赖拓扑逐项推进，不需要同时开启多个未验证任务。多人并行时 CE-03 与 CE-07 的目录 schema、CE-09 与 CE-19 的并发协议、前端路由注册等公共文件由指定集成人员串行协调。

## 5. 里程碑与真实可用范围

### MVP：可配置、可限制、可展示

必须完成 CE-01～CE-09、CE-11～CE-14、CE-18～CE-20。支持平台管理套餐及专项授权、租户默认免费开通、直接 API 权益控制、可信 Vue 呈现、成员／设备存量额度及选定真实字段保护。人工触发套餐切换可完成。

不宣称已经具备在线支付、自助订购、可靠预约到期或 IoT 长任务商用授权。日期相关保护必须由 CE-06 拒绝过期权益；缺少调度时不能持续享用过期套餐。

### Full Runtime：完整核心订阅闭环

必须完成 CE-01～CE-21 以及 CE-25。增加持久化开通任务、自助免费／人工可信确认流程、预约与到期、失败重试／对账和附加包。在线支付供应商不构成此里程碑的必需依赖。

### Production Core：核心能力生产资格

在 Full Runtime 基础上完成 CE-24、CE-26，满足迁移、部署与运维前置条件。没有 CE-22 不可对外声明“在线付费自动开通已投产”；没有 CE-23 不可声明“真实 IoT 长任务已覆盖”。

### 条件扩展资格

Paid Production = Production Core + CE-22 的真实供应商沙箱／回调验证及生产配置审核。

IoT Job Production = Production Core + CE-23 的真实任务、执行器和设备回执验证。

这些清单在 tasks.json 中定义 `profiles`，检查器报告结构及依赖闭包；初始全部未达成。

## 6. 相对独立与回滚边界

R1 可单独输出可售能力目录；R2 可先通过管理员专项授权验收而不等待价格和支付；R3 可通过真实 API 验收而不等待 Vue；R4 的基线／身份可独立验收；R5 不依赖支付供应商；R6 不依赖复杂计费；R7 的外部集成只在满足真实条件时启动；R8 只消费已交付能力，不暗中实现缺失业务。

每项回滚停留在自己的行为、路由和数据版本边界，不把“禁用全部权限检查”“回退整个 biz”或“恢复旧数据库覆盖新审计”作为回滚方案。

## 7. 首个任务

领取 **CE-01：固定实施基线、领域契约与运行时探针**。完成后由台账计算 CE-02、CE-11、CE-12 的就绪情况；不直接跳到大页面开发或一次实现整条路线。
