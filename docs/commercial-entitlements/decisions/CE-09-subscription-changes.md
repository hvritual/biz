# CE-09 预览、确认与原子套餐切换

## 范围与依赖
本任务依赖已 DONE 的 CE-06、CE-08，业务基线为 `fed9051bae618ab28df200038682f808c82e854b`。Yunka 保持 `33b98ceba57494abda2299e4f0290a5651dab4bc`，不再改框架。使用现有可信平台身份、typed child、唯一 Executor/根 UoW、CE-06 版本快照和事务屏障。

仅交付后端人工可信套餐变更 API：预览、确认、预览回读、按 change_id 回执回读。无客户端已支付字段，没有支付供应商、账务、前端、Outbox、预约执行器、实际资源消费或跨域数表。CE-09 的预约确认不代表预约已经执行。

## 输入、权限和价格边界
预览需要 `platform.subscription.manage` 及 tenant/plan/catalog 读取权限；确认必须持有独立的 `platform.subscription.confirm`（并具有声明的读取闭包）。两者均拒绝携带 TenantID 的租户主体。预览归属于创建平台主体，其他平台主体不能查看或消费该私有预览；有平台审计读取权限者可按租户和 change_id 读取已确认回执。后续租户自助由独立路线实现。

全部确认均归类为 PLATFORM_MANUAL_APPROVAL，明确表示有权平台主体确认商业操作，不是支付凭证。没有 price_ref 只表示未配置价格引用，不当作价格为零；有 price_ref 的预览标记需要平台人工确认。不接收付款状态、价格、资源使用量、有效权益或快照版本作为事实输入。写请求必须使 request_id 与 transport idempotency key 相同，禁止同一主体同一操作的同键绑定另一租户或另一载荷。

## ChangePreview
服务端读取源不可变套餐、当前订阅、权威权益来源及快照、技术目录，再读取目标套餐资格。保存不可变预览，绑定：主体、规范化请求、源订阅修订号与内容、源权益版本、快照 entitlement_version、目录 epoch、目标套餐版本与内容摘要。预览 hash 使用确定性 JSON SHA256，读取核对列与载荷。

预览展示新旧套餐条款、合成后的能力/字段/额度视图、依赖、使用量已知性与超额处置、有效时间及失效时间。预计生效权益合并保留专项授权、安全限制和附加来源；投影视图的 entitlement_version 恒为 0，不得作为当前快照缓存或授权依据。创建预览不替换有效来源，只允许按 CE-06 的现有机制准备派生快照。

预览有效期最多十分钟，并受当前快照 valid_until 截断；确认必须重新校验。立即生效时刻为确认根事务内最后数据库时间检查的准入点，预览的时间仅为估计；回执记录实际准入时刻。不得把它描述为提交墙钟时刻的强制取消保证。

## 操作与期限
`SWITCH` 的 UPGRADE/SAME_TIER/DOWNGRADE 由服务端条款比较判定，不接收客户端套餐等级。任何能力/字段/额度减少或有效期收缩均保守归为降级，混合增减也归为降级。默认升级/同级立即生效；默认降级为当前有限期限结束，下周期不硬编码为自然月。源无限期套餐没有可推导下周期，须显式提交将来生效日期。显式时间转换为 UTC，并向上归一到数据库微秒精度，不能因截断而提前生效；规范化后的时间写入预览、摘要与回执。时间必须晚于数据库当前时间，过去日期拒绝；领域输入只接受有效年份和规范微秒精度。

`RENEW` 只允许原固定天数版本；在 max(准入时间, 当前期限结束) 上增加该版本天数，保留尚未消耗的期间，重新明确未来续期意图。`STOP_RENEWAL` 只改变续期意图，不削短当前权益，不取消外部扣款；原套餐停售后仍允许停止续期。它不引入自动扣款或自动续期机制。

CE-08 旧订阅 JSON 没有修订号/期间时，按仍保留的原套餐版本和原 created_at 解释为 revision=1 及原期限，保持原 source namespace。新版初始化直接填入这些字段；历史回执不重写，不进行隐式全量迁移。

## 确认、幂等和原子性
固定锁顺序：共享目录 epoch → 该租户唯一基础订阅 UPDATE → 套餐当前/版本共享读取 → 权益源状态/来源 → 快照头。商业写/撤权使用既有 CE-06 屏障；不另开 root transaction，不持事务等待网络服务。

确认先查不可变回执。完成请求的同键同载荷直接返回原回执，即使预览已过期或套餐后来停售，也不改写完成事实；同键不同载荷和同预览不同确认键拒绝。仅对拥有数据库响应回执的两条 CE-09 写 operation 复用现有 completed-claim replay 适配，保留认证、权限、必填键、执行中互斥、原子 finalization 与其他操作的原行为。

尚未完成时重查预览、源订阅/来源/快照/目录版本、目标资格和摘要，并调用类型化额度策略。最后再次检查数据库时间未跨预览到期。立即切换在同一根 UoW 中撤销旧 PLAN generation、插入新 generation、推进 source version、保存真实不可变快照、更新唯一基础订阅、保存 ChangeReceipt 与审计。保留所有已撤销来源、历史套餐及专项授权；任一阶段失败整体回滚。

预约只保存 SCHEDULED 回执与订阅 pending_change_id，并推进订阅 revision；不更换当前 plan、不增大 source version、不撤销旧来源。一个待执行变更排斥第二次预约/修改，防止旧预览抢占；执行和取消属于后续持久化执行路线，本任务不提供假执行按钮。预约时间经过也不能自行标记 APPLIED。

## 额度策略与存量
通过 `QuotaChangePolicy` 的本地同步类型化能力接入；实现必须使用当前根事务，禁止远程网络请求。CE-19 尚未接入时，降额 usage_known=false，证据明确为未接入，不填造零使用量。

未知或超额降额不能立即应用；可以保存待重新校验的预约意图，并明确 quota_validation_required。未来执行器必须重查真实使用量和策略，不能直接使用预览中的旧计数。已知使用量必须附带可解释的权威证据；适配器不能改写目标额度。存量资源绝不因本操作删除，本轮没有实现额度扣减/预占或设备/成员原子消费。

## 发现的基础衔接缺口
固定基线的 `decodeSources` 只接受 override，虽然 CE-08 已合法持久化 PLAN 来源。独立诊断 run `34470537733` 在真实 MySQL 创建租户后读取权威源，复现 `ENTITLEMENT_TRUSTED_CONTEXT_REQUIRED`；诊断成功不是业务资格。

必要修复为允许经过形状/租户/列版本核验的已知 plan、addon、override 来源。与此同时，List/Revoke override 用例仍明确限于 override，禁止将合法套餐来源暴露为可编辑例外授权。CE-09 还逐项核验当前 PLAN generation 与绑定的原套餐条款/期间一致，缺失、伪造或篡改时失败关闭。后续真实源读取及不可越权修改反例必须通过。

## 存储、回滚及未验证项
新增 additive 迁移：change_previews、change_receipts、change_audit；通过 FK RESTRICT 保留租户、源版本、目标版本和回执历史，摘要核对持久化载荷。迁移先于新二进制启用；AutoMigrate 仅开发和资格环境。不得回拨 revision/source_version、删除来源/回执或通过直接改旧套餐进行回滚。

已应用变更需通过新的、重新预览和确认的补偿变更恢复旧方案，版本继续递增；待执行变更先停执行并按真实状态处置。停止写入口可以控制事故范围，但不能把旧回执删除伪装成未执行。
