# CE-10 Outbox 与持久化开通任务

## 目标与固定基线
基于 main `12f33db5632a81c04b9de7634b5d37baf5a2bb1a`，CE-09 硬依赖已 DONE。Yunka 保持 `33b98ceba57494abda2299e4f0290a5651dab4bc`。本文件定义实现语义，不是 PASS 回执；完成状态以 tasks.json 和真实验证证据为准。

## 两条明确路径
纯数据库变更继续使用 CE-09 的根事务直接 APPLIED，同时写入不可变 Outbox。配置要求外部准备的立即变更只持久化原确认回执 PROVISIONING、唯一 task 和 pending_change_id；递增订阅 revision，不提前撤销旧来源或增加新权益。原确认回执保持不可变，最终进度及实际 entitlement_version 在任务完成回执中读取。
预览绑定服务端本地 ProvisioningPolicy 返回的有序、具名、版本化步骤；确认和实际激活均重新核验。不得从客户端请求接收任意 URL、脚本、适配器、付款或 READY 事实。政策只读本地可信配置，不在根事务内访问外部服务。
CE-09 SCHEDULED 仍只是预约意图，不自动生成可执行外部准备，不执行或取消预约。预约执行属于 CE-16。本轮不引入支付、UI、真实额度消费或任意脚本执行器。

## 外部准备与恢复
每步有稳定外部幂等键、步骤状态、副作用状态、累计尝试次数、周期预算、对账次数、证据和错误码。预先编译、明确注册的 PreparationAdapter 在数据库事务外调用；Prepare 与 Reconcile 分开。
小根事务先抢占任务并提交租约；执行网络动作后，用相同租约令牌在新根事务回写。租约到期重新取得所有权时，先按稳定键 Reconcile，不能盲目重做可能已成功的外部写入。旧 worker 的迟到结果不能覆盖新令牌。
READY 必须有可回查证据。RETRYABLE/PERMANENT 只适用于已证实无副作用；UNKNOWN、panic、非法结果进入 RECONCILIATION_REQUIRED，不能解释为成功或安全取消。缺少准确适配器版本时不降级为 mock success。
自动准备每周期最多 1–10 次，激活最多 3 次；明确人工重试最多 10 个周期，保留累计次数、证据和稳定外部键。单步骤自动对账总数最多 32 次，超限停止并暴露待处置。开通审批任务期限 24 小时，到期不再自动开权。数据库 fencing 不能撤销已经发出的网络请求；外部适配器必须遵守其真实幂等和对账协议，不声称跨供应商恰好一次。

## 实际激活
仅每个步骤真实 READY 后，经原 Executor 的内部 typed child 进入 SubscriptionChanges。最后重新验证：原平台确认主体及预览摘要、pending 订阅 revision、来源/快照/目录版本、目标套餐资格与摘要、步骤政策版本、额度策略、数据库时间、租约和审批期限。
旧 PLAN 来源撤销、新来源写入、来源版本、真实快照、唯一基础订阅、任务完成及审计、APPLIED Outbox 在同一根 UoW 提交。任一失败全部回滚。随后另一个小根事务记录失败原因，不能把事务内未提交的部分结果当作成功。
原 IAM、DataScope、CE-06 屏障、最后 owner 约束保留。不跨域直接写 Access repository，不引入第二套 Executor/UoW。

## Outbox / Inbox
Outbox 是不可变订阅事实，绑定 tenant、subscription aggregate、aggregate revision、change、task、status、source version 和真实 entitlement_version。业务提交成功前没有可投递事件；投递状态独立存储。
采用数据库轮询、有限租约、最多 5 次自动投递尝试。Inbox 使用 consumer_id + event_id 去重并验证载荷摘要；内部订阅通知投影只向较大 aggregate_version 前进。乱序旧事件记为 STALE，精确重复不重新开通，不同载荷复用 ID/版本失败关闭。Inbox、通知投影、ACK 同一小事务，崩溃后可重投。通知投影不作为权益 Guard 的事实源。
投递失败保留原事件、错误及尝试记录；达到预算为 DEAD，不删除事件假装完成。CE-17 后续负责更广泛运营处置，不假称已有批量修复服务。

## 查询、重试、取消
公开五个用例：任务读取、分页列表、幂等重试、安全取消、投递列表。都要求真实平台身份和明确权限；租户即使持有同名权限也不成为平台主体。任务修改绑定原请求幂等键、主体、载荷和 expected_revision，回执持久化后跨 runtime 重放相同原结果。
抢占、步骤回写、实际激活、投递确认是无 HTTP/RPC 入口的内部 operation。worker 每次根调用使用现有持久化平台凭据重新认证和授权，无内建超级权限。自动轮询可显式启用；同一 worker 也可由嵌入进程调用一次性处理入口。
只有任务非 RUNNING、且所有步骤均确认 ABSENT 时允许取消；取消、释放 pending 订阅、审计和取消事件同事务。已准备资源、未知外部结果不得删除或强行取消，需要供应商真实补偿或对账后处置。

## 默认创建边界
CE-08 承诺默认套餐立即可用。因此需要外部准备的默认套餐不能经创建路径直接开权；仅能继续匹配另一个显式 DB-only 合法兜底，否则整笔创建拒绝。已有可用基础套餐后，可通过 CE-10 变更准备外部资源；这不等于完整外部注册产品。

## 验证、迁移与回滚
验证使用真实 MySQL、实际 API/内部 Executor、故障注入、并发、数据库和 runtime 重启。受控测试适配器仅证明边界与恢复协议，不冒充已接入供应商。生产适配器、支付、预约调度、真实资源用量统计及生产负载测试不在本轮范围。
新增 additive SQL 先于二进制启用；AutoMigrate 仅开发/资格。事故时可停止 worker 和变更入口，保留 Outbox、Inbox、任务、步骤、租约、回执和历史；恢复后按版本与租约回读。外部已发生动作仅允许真实补偿，不删租户、回拨权益版本或抹去审计。
