## 反例与故障验证

### 已证实框架缺口

Application 图无环：

```text
commercial/entitlement_management -> access/tenant_lifecycle
access/tenant_lifecycle -> commercial/subscription_management
commercial/subscription_management -> commercial/plan_management
commercial/plan_management -> commercial/module_catalog
```

生成 Go 包图有环：`internal/access/application <-> internal/commercial/application`。

`pkg/contract/c9_application_codegen.go::renderC9CapabilityPorts` 把目标完整 Application 接口作为 wrapper 内部字段/构造器参数，跨域导入对方 application 包。各 Application 按 domain 共用一个包，导致无环应用图压缩后成环。Access 的生成 tenant-lifecycle capability 文件与 Commercial 的生成 entitlement-management capability 文件构成实际反向导入。

单向依赖对照通过，排除了“任何 child 都不能生成”的错误归因。两次生成一致，排除了漂移是当前主因。检查器通过只说明声明/派生一致，不保证消费者 Go 包可编译。
