## 变更清单
确认套餐变更时，订阅/开通状态与事务型 Outbox 同根事务持久化；Inbox 与聚合版本保证重复及乱序通知不能覆盖新状态。持久化开通任务记录步骤、动作、审计、重试时间、租约 owner/token 和失败码。外部 provider 工作在数据库事务外执行，使用稳定 provider 幂等键；若外部动作是否成功不确定，恢复路径执行 Reconcile，而不是重复 Prepare。
目标套餐权益不会因“已确认”提前生效：需要外部准备的变更保持旧有效权益，直至所有必要步骤 READY 后才由纯数据库事务切换；无外部步骤时可直接完成。平台提供任务查询/列表/重试/受限取消及 delivery 查询接口；取消仅允许已知无外部副作用的工作。worker 使用服务端 token，并在每次 claim 前实时检查 `platform.provisioning.execute`。

## 反例与故障验证
真实 MySQL 首轮暴露并修复了四项问题：`change_id` 外键字符集/排序规则不一致导致 3780；回执 schema 缺少独立 PROVISIONING 状态；后台 worker 被误判为 child-only Guard；等待行锁后仍使用锁前 DB 时间判断 lease。修复保留 FK/RESTRICT、fail-closed 授权和 lease token fencing，没有删除约束或测试。
另以真实 MySQL 证明外部动作完成后、观察结果提交前进程中断的路径：任务保持 RUNNING、旧权益保持不变；数据库真实重启并等待真实 lease 到期后，worker 使用原 provider key Reconcile，不重复 Prepare；仅当结果 READY 后才激活目标权益。worker 权限撤销后无法 claim/provider work，恢复授权后才继续。
