# R3 套餐版本与订阅生命周期

独立产物：通过真实 API 管理套餐与订阅，不必等待 Vue 或在线支付。默认免费开通、人工可信变更可先运行；外部服务开通由持久化任务承接。

通用规则见 [执行约定](../04-execution-contract.md)，跨路线交接见 [契约](../01-requirements-and-contracts.md)。

## CE-07 套餐版本、发布与适用资格

依赖：CE-02
验收标识：TestCE07

**目标与输入**：将已就绪能力组合为确定、可追踪的商业套餐，而不是在租户表增加一个可随意改含义的 plan_id。

**交付要求**：实现 plan.proto、Plan/PlanVersion 及版本权益，包含模块／能力、字段策略模板、额度、有效期策略和适用范围。草稿可编辑，发布版本不可原地覆盖；修改生成新版本。校验能力存在、技术就绪、依赖闭合、额度合法、强制脱敏不可放宽。停售仅禁止新订购；被订阅引用的版本不可硬删除。为价格保留独立引用，不在商业能力解析器内计算费用。

**改动边界**：套餐应用、schema／迁移、契约及平台权限；不实现支付、订单账务或批量迁移，不复制 IAM 角色作为套餐。

**验收**：V1 发布后编辑被拒绝，V2 不改变 V1；停售后老引用仍可读取，新申请按资格拒绝；不存在能力、依赖不足、非法字段策略、并发草稿修改和重复发布有确定结果。角色管理员不能发布平台套餐。

**回滚**：新版本停售或发布修正版本，保留历史引用；禁止直接改旧版内容。

## CE-08 默认开通规则与原子租户订阅初始化

依赖：CE-04、CE-07
验收标识：TestCE08

**目标与输入**：将已发布套餐与现有 Tenant／Owner 初始化组合，使新租户不依赖人工补表即可获得默认权益。

**交付要求**：实现 subscription.proto 的初始订阅能力；默认规则具有明确匹配优先级、资格、规则版本、命中解释和安全兜底。平台控制规则，租户不能提交任意高权限套餐作为注册结果。通过 typed child Operation 在根 UoW 中创建 Tenant／Owner、基础订阅与可用权益；关联已发布套餐版本。同一租户同一时间只有一个基础订阅；重试返回同一开通结果。未提供真实注册前端时以现有租户创建入口验收，不顺带发明整套注册产品。

**改动边界**：商业订阅应用、声明式跨应用组合、现有租户 bootstrap 的必要契约调整和装配；不从商业域直接写 Access Repository，不损坏最后 owner 规则。

**验收**：默认规则与特定规则命中确定；套餐不存在／停售／不合资格时拒绝或使用已配置合法兜底。注入每个 child 失败，不能留下“租户有了、owner 没有”或“订阅已生效、权益缺失”；重复与并发初始化不产生双基础订阅。既有 bootstrap 压力测试回归。

**回滚**：恢复默认规则版本；失败记录保留。已完成租户不删除，需通过新的订阅变更修正权益。

## CE-09 预览、确认与原子套餐切换

依赖：CE-06、CE-08
验收标识：TestCE09

**目标与输入**：基于当前订阅／权益版本，完成可回读、可幂等的人工或免费套餐变更 API。

**交付要求**：创建 ChangePreview 与 ChangeReceipt；预览包含新旧能力、字段、额度、依赖、存量影响、生效时间与失效时间，绑定源订阅／权益版本、目标不可变套餐版本和合法输入。确认重新检查资格及版本；立即与预约分别记录。以单根事务更新订阅、生效权益、变更与审计；旧权益保持到真正切换。支持升级、同级切换、续期、停止续期和降级；降级默认下周期，资源超额不删除存量。超额策略通过类型化校验接口，CE-19 补齐原子资源消费。无真实费用结算时只允许免费或已由有权平台主体确认的操作。

**改动边界**：订阅用例、商业类型化组合和必要 quota-policy 接口；不接受前端传入“已支付”，不直接跨域数表，不持 DB 事务等待外部服务。

**验收**：过期预览、目标被停售、同时升级／降级、源版本变化、同幂等键不同载荷均正确拒绝或返回已有回执；超时后按 change_id 回读；回滚不留部分权益。确认订单和付款状态必须由可信服务器结果决定。预约本任务只持久化，不伪称已具备调度；日期安全由 CE-06 保证。

**回滚**：创建补偿变更恢复已确认的旧方案并增加版本，不回拨版本或删除原变更。处理中变更先停止执行并核对真实状态。

## CE-10 Outbox 与持久化开通任务

依赖：CE-09
验收标识：TestCE10

**目标与输入**：把“数据库切换成功后的通知”和“需外部资源准备的开通”变成重启可恢复的流程。

**交付要求**：与业务事务同写 Outbox；建立 Inbox 去重、aggregate_version 顺序防护、开通步骤状态和有限重试。区分订阅状态与 provisioning 任务状态；纯 DB 变更可直接 applied，外部初始化只有准备就绪后才切换有效权益。提供任务查询、失败原因、幂等重试与明确的取消边界；租约／执行权可在进程退出后恢复。通知先面向内部事件，不强加 Redis／消息中间件为必选依赖，可从可靠数据库轮询派发开始。

**改动边界**：商业事件与任务基础设施、运行组件装配、任务 API；不新增任意脚本执行器，不接真实支付供应商，不把不确定外部结果伪装成功。

**验收**：事务回滚无事件；提交后崩溃可补投；重复／乱序事件不重复开通且不覆盖新版本；执行中重启恢复；永久失败暴露真实步骤。用测试边界故障注入验证，不在生产路径加 mock fallback。已生效回执能对应同一 entitlement_version。

**回滚**：停止派发并保留待处理 Outbox／任务，按版本恢复消费；外部已发生动作只允许按其真实补偿协议处理，不能删除记录假装未发生。
