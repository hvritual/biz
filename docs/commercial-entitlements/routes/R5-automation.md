# R5 自助开通、预约到期与恢复对账

独立产物：不依赖在线支付供应商的自动订阅闭环。依靠已交付 API、可信身份与持久化任务，免费变更或人工可信确认后自动推进；没有外部条件时不伪造付款结果。

执行规则见 [执行约定](../04-execution-contract.md)，释放标准见 [验收](../03-acceptance-and-release.md)。

## CE-15 租户自助选择、预览与确认套餐

依赖：CE-10、CE-14
验收标识：TestCE15

**目标与输入**：在真实租户控制台交付可用套餐选择、升级／降级／续期／停止续期及开通结果，而非前端模拟切换。

**交付要求**：提供租户可购买范围查询与套餐对比；展示当前／目标权益差异、超额影响、生效时间和预览有效期。确认携带服务端认可的预览关联与幂等标识，跳转或展示 change_id 的可查询进度。免费方案可直接进入业务流程；需人工确认的请求进入待确认，由明确权限的平台主体核验后推进，租户不能自填已付款。区分旧套餐仍生效、新套餐开通中、失败及已生效。未完成 CE-22 时隐藏真实在线支付入口或明确未提供，不做假的支付弹窗。

**改动边界**：web 租户订阅 feature、服务适配、必要的自助范围／申请契约；不得在前端计算最终权益、擅自重写 CE-09 状态机或放宽平台权限。

**验收**：真实 API 完成免费升级、预约降级申请、续期／停止续期；请求超时后回读，不重复创建；版本变化强制重新预览；普通成员无变更权时不可操作；失败显示真实阶段而不显示已生效。与后台最终订阅／权益版本一致，E2E 用例有 CE-15 标记。

**回滚**：关闭自助新申请入口，已经接收的 change_id 继续可查；不能把用户重新导向演示套餐状态。后台任务按当前真实状态处理。

## CE-16 预约切换、试用及授权到期调度

依赖：CE-10
验收标识：TestCE16

**目标与输入**：自动执行持久化的时间规则，不依赖用户登录或浏览器定时器触发。

**交付要求**：实现多实例安全的到期扫描／领取与逐任务处理；统一服务端时钟，持久化 UTC 时刻并记录业务时区，定义时间区间为起点包含、终点不包含。支持预约套餐、试用到期、例外授权到期、续期边界及 configured grace/restricted 状态。每次转换校验当前订阅版本、源状态与目标合法性；旧到期任务不得撤销新续期。无外部付款证明不自动续成付费授权。调度延迟时 CE-06 的时间边界仍阻止过期能力；到期保留明确恢复入口，不等同 Tenant.Suspend。

**改动边界**：商业运行组件、状态转换应用、持久化领取／租约、配置与监控；不修改用户机器时间、不在 Application 自建根事务，不硬编码真实宽限期天数。

**验收**：执行到边界前／恰好边界／之后；并行 Worker、进程重启、重复扫描、跳过扫描一段时间、时区／夏令时显示、旧任务迟到、同时续期与降级等场景正确。每项结果关联 change_id/来源及版本，无双生效套餐。暂停调度不导致过期授权无限延长。

**回滚**：暂停新领取并保留已持久化任务，修正后按当前版本重放；不能通过延长全部租户有效期掩盖调度故障。

## CE-17 开通恢复、对账与运营处置

依赖：CE-10、CE-15、CE-16
验收标识：TestCE17

**目标与输入**：让“卡住、失败、版本不一致”成为可见且可处理的业务状态，闭合执行回执、回读与对账。

**交付要求**：对比订阅来源、专项授权、当前权益快照、开通任务、Outbox/Inbox 与已收到的外部确认；区分可自动修复的派生漂移和需要人工处理的权威事实冲突。提供平台任务列表／详情／受控重试／取消或补偿请求；保留原始失败、重试次数与操作者。定义重试上限、隔离队列或等效停止重试状态及告警。仅因通知失败不能重复创建外部资源；不因为人工点重试跳过版本或身份验证。

**改动边界**：商业恢复用例、任务查询／处置 API、相关 web 页面与监控；不直接手改快照、账务、Outbox 状态以冒充成功，不重造通用工作流平台。

**验收**：提交后宕机、事件丢失、重复回调、旧任务覆盖尝试、派生快照漂移、永久外部失败均可定位。可修复问题恢复后 source_version 与实际状态一致；不可自动修复者保留明确阻塞。权限不足的平台操作员也不能执行处置动作。E2E 可从租户 change_id 追溯平台任务结果。

**回滚**：停止自动修复、保留只读诊断与原始事件；不删除冲突事实。已发生外部动作按其协议补偿并记录不可逆部分。
