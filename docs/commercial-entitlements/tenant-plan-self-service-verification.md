# 租户套餐自助选择与开通验证记录

更新时间：2026-09-29

## 当前可验证链路

1. 租户从可信会话读取当前租户的可选已发布套餐，客户端不携带 `tenant_id`。
2. 套餐卡展示价格、有效期、模块数量和适用范围；选择后展示模块能力、额度、字段策略。
3. 预览由服务端重新计算资格、用量、依赖、目标套餐版本和预览哈希；租户须先在确认弹窗核对套餐、价格和生效时间，确认请求仅携带预览标识、哈希、原因和幂等键。
4. 无价格引用的确认可进入 `APPLIED`、`SCHEDULED` 或 `PROVISIONING` 回执。预约和准备中回执每 15 秒读回一次，也允许租户手动刷新；进入终态后刷新当前套餐信息。
5. 有价格引用的套餐只能创建锁定套餐版本、币种、金额和渠道的订单；页面不会将订单创建显示为已支付或已开通。

## 权限与数据边界

- 列表、预览、确认、回执和支付订单均使用租户可信会话上下文；租户边界由服务端主体决定。
- 预览/确认使用服务端发出的哈希和幂等键，前端不提交金额、币种、套餐版本的结算事实。
- 付费套餐的确认按钮保持不可用，直至真实支付核验与开通确认链路具备；当前渠道适配仅覆盖微信 Native 和支付宝 Page 的接口边界。

## 生产资格结论

本记录证明当前工作区的租户自助页面、无价格引用的套餐确认、结果读回和支付 fail-closed 边界可用；它不构成生产发布认证。`docs/commercial-entitlements/tasks.json` 的 `FULL_RUNTIME` 当前为 14/22，且没有认证证据；`PAID_PRODUCTION` 为 14/25。因此不能将当前工作区称为已满足生产上线要求。

共享 MySQL 资格脚本已在释放 `biz`、`biz-idp` 连接后运行，并在结束时清除了恢复标记、恢复原始数据。本轮首先发现并修复 `biz_commercial_payment_orders.change_id` 缺少 `ascii_bin` 定义导致的 MySQL 3780 外键不兼容；修复后商业迁移穿过 CE-08/09/10/16 分组。整套脚本仍因通知延迟资格阈值失败，不能作为全绿集成认证。

## 未作为完成项的外部前置条件

真实微信/支付宝商户调用、回调验签、主动对账、退款/争议策略和支付成功后自动确认，仍需要支付凭据、回调地址和运营策略。这些条件未提供，且用户已要求跳过真实支付；因此不得把当前实现表述为“付费套餐已可自动开通”。
