## 1. 范围和解释规则

管理对象是已经签约的承租企业及其租赁期间的关系、承诺、使用、服务、变更、结算和合作结果。长期租赁为主，不将“日常租赁”理解为按天出租。

沿用原故事的四组组织：A 客户关系；B 日常跟进；C 费用与业务变化；D 合作价值。保留福利型、接待型、经营型三个使用目的，多点位和总部签约是附加复杂度。

本清单有 **16 个页面级功能、80 个页内功能项、48 条功能验收场景**。一张设计图对应一个页面级功能，查询、详情、创建、编辑等页内动作不是额外独立页面；其抽屉、弹窗和异常状态仍属于验收范围。16 张主场景设计图不能替代所有交互状态的实现与测试。

来源分层：

- S：原故事明确的目标或限制，逐条记录在各功能的“源故事”中。
- D：为实现故事提出的产品设计，包括字段、状态、路由、角色划分、优先级、阈值配置和验收场景；均为设计建议，不是市场调研实证。
- R：仓库实际读取事实，只限本文件第 7 节列出的内容。

不新增市场规模、真实发生频率、真实服务承诺、固定收费标准或已验证流失模型。不做线索营销、支付交易、完整 ERP、仓储采购、通用维修管理、自动停机催收、信用评分和无人确认的自动续约。工单、配送、账单等在此聚焦客户协作和事实关联，不借此重建所有外围系统。

## 2. 系统边界与角色

功能归属 **租户运行系统 / 客户成功**。平台管理系统仍负责租户、套餐、额度、功能模块和全局设置，不默认获得承租客户业务详情。

租赁商所属租户管理自己的客户关系；承租企业可以也是平台租户。`customer_id` 是业务关系标识，`tenant_id` 是隔离边界，两者不能混同，也不能按企业名称自动打通。双方关联、点位共享、有效期与历史数据权限需要明确授权。

| 角色 | 工作范围 | 关键限制 |
|---|---|---|
| 客户经理 | 客户、联系人、承诺、跟进、续租、扩点 | 仅授权客户及点位；成本利润不默认开放 |
| 运营/补料协调 | 履约、使用调查、物料协同、变更执行 | 不自动获得合同金额或全客户可见权 |
| 客服/服务负责人 | 体验问题、持续问题、回访确认 | 问题关闭不能代替客户确认 |
| 租赁商财务 | 费用依据、对账争议、可归属收入成本 | 金额和成本字段独立授权 |
| 租赁商负责人 | 本租户经营视图、贡献分析 | 不能跨租户查看未共享数据 |
| 承租企业行政/财务/点位负责人 | 已共享的本企业事项、账单、报告及确认 | 不得查看租赁商内部备注、其他客户或内部利润 |

上述业务角色是权限设计，不表示要新建一套登录与角色系统；正式接入复用 Access/IAM 的身份与数据范围。

## 4. 详细功能清单

### A. 客户关系

### F01 客户档案与全景 · CS-01 · UI-01

**源故事 S：** 同一客户被总部、门店和财务记录拆散；客户经理希望从一个入口理解总部、签约和付款主体、点位及关联事项，并避免重复汇总。

**用户/入口：** 客户经理；客户成功 → 客户档案 → 选择客户。

| 编号 | 页内功能 D |
|---|---|
| F01.1 | 客户建档、查询、使用目的分类、归属负责人及合作状态维护 |
| F01.2 | 总部/子公司/签约主体/付款主体的角色关系维护；允许同一主体承担多个角色 |
| F01.3 | 汇总授权点位和有效设备投放；进入点位或投放记录，不用当前设备归属覆盖历史 |
| F01.4 | 按客户聚合承诺、反馈、问题、变更和沟通时间线，标记来源与责任人 |
| F01.5 | 疑似重复档案提示及人工关联/合并评估；留存旧标识、来源和操作记录 |

**核心信息：** 客户 ID、名称、使用目的、运营商租户、关联承租租户、主体角色、点位、负责人、合作状态、更新时间。合作状态建议为筹备/服务中/暂停/已结束；业务合作结束不等于注销平台租户。

**输出：** 可追溯客户全景及关联记录。**边界：** 同名不自动合并；汇总按记录 ID 与有效期去重；共享方只见授权部分。

**验收：** A01 给定同一企业承担签约与付款角色，汇总收入时只计算一次原始记录。A02 给定门店问题，进入客户全景时可定位对应点位、合同引用和负责人。A03 给定无跨租户授权，按名称搜索另一租户客户时不返回其详情。

### F02 联系人与交接 · CS-02 · UI-02

**源故事 S：** 联系人离职后通知失效，新任负责人缺少服务知识和未结事项；旧联系人应退出通知和授权范围，历史应保留。

| 编号 | 页内功能 D |
|---|---|
| F02.1 | 联系人及角色台账：决策、付款、协调、现场，可按客户与点位维护 |
| F02.2 | 联系方式和适用范围维护，记录有效/待接手/已退出状态 |
| F02.3 | 发起交接单，指定接手人、应交接事项和生效时间 |
| F02.4 | 承诺、未结问题、补料安排和操作资料组成交接清单，逐项确认 |
| F02.5 | 跟踪通知与授权变更结果；失败进入待处理，不因保存联系人就宣称权限已回收 |

**用户：** 客户经理、承租企业负责人。**信息：** 联系人角色、点位、关联账号引用、交接人、接手人、确认记录。**输出：** 已确认交接和后续动作。联系人不是账号；移除业务联系不等于删除全局用户。

**验收：** A04 新负责人可查看其授权范围内的未结事项和资料。A05 生效后旧联系人不再收到新业务通知；授权失败有明确阻塞项。A06 更换联系人不会删除原沟通记录或操作者归属。

### F03 服务承诺与履约 · CS-03 · UI-03

**源故事 S：** 销售承诺未传递给运营；约定需要来源、确认状态、责任人，讨论中的内容不能成为正式承诺。

| 编号 | 页内功能 D |
|---|---|
| F03.1 | 承诺台账：服务项目、适用客户/点位、合同或沟通来源 |
| F03.2 | 草稿、待确认、已确认、已作废状态及版本留存 |
| F03.3 | 记录频率、起止时间、触发条件、例外和明确服务责任人 |
| F03.4 | 生成或关联履约事项，显示待执行、处理中、待确认、已完成和逾期标记 |
| F03.5 | 履约证据、客户确认、变更引用与到期未兑现跟进 |

**用户：** 客户经理、运营。**输出：** 可执行承诺及履约记录。**边界：** 不内置统一巡检周期、免费范围或备用机时限；合同确认方式与证据可配置。

**验收：** A07 未确认草稿不能进入正式应履约清单。A08 运营能从事项追溯到确认来源和适用条件。A09 到期未兑现显示责任人与后续动作，单纯修改截止日期不能抹除原逾期事实。

### B. 日常跟进

### F04 每日客户工作台 · CS-04 · UI-04

**源故事 S：** 工作被消息顺序驱动；客户经理需要知道应先跟进谁、为什么、依据是什么，并可人工调整。

| 编号 | 页内功能 D |
|---|---|
| F04.1 | 汇总授权范围内待跟进客户，按到期事项、客户影响和人工优先级组织 |
| F04.2 | 每项展示触发原因、证据来源、发生/更新时间、负责人和建议动作 |
| F04.3 | 创建回访、分派、修改优先级、排除或稍后处理，记录原因与到期时间 |
| F04.4 | 同一客户相关信号聚合，关联原事项，避免重复待办 |
| F04.5 | 跟进结果回填与原事项回读，不用完成待办代替服务问题关闭 |

**状态：** 待处理/处理中/待反馈/已完成；排除有理由，稍后处理有恢复时间。**输出：** 当日行动队列。**边界：** 先使用可解释规则；不以黑盒健康分作为唯一排序。未接入信号源明确提示。

**验收：** A10 每条优先事项均可查看原因和证据时间。A11 人工排除有记录且不会删掉原始业务事实。A12 标记回访完成后，未恢复的服务问题仍保持未解决。

### F05 使用变化与原因调查 · CS-05 · UI-05

**源故事 S：** 出杯下降可能来自搬迁、停业、维护负担或体验；需区分数据缺失与低使用，确认原因后再采取行动。

| 编号 | 页内功能 D |
|---|---|
| F05.1 | 按客户/点位/周期展示使用变化，显式显示数据完整性和可比区间 |
| F05.2 | 配置可解释的变化观察条件；阈值是租户配置，不声称行业标准 |
| F05.3 | 关联营业日、人数变化、停业搬迁、设备可用和近期反馈背景 |
| F05.4 | 创建调查，记录假设、联系情况、已确认原因、证据与负责人 |
| F05.5 | 跟进培训、服务或方案调整，观察后续结果并结案 |

**状态：** 待核实/调查中/原因已确认/行动中/已复盘。**输出：** 有证据的原因与措施。**边界：** 数据断流不显示为零；下降不直接等于流失或违约；不自动调整服务。

**验收：** A13 数据缺失的时间段不按零杯参与下降判断。A14 登记搬迁后可解释变化且保留原曲线。A15 未确认原因不能展示为确定的流失原因。

### F06 体验反馈与回访 · CS-06 · UI-06

**源故事 S：** 口味、奶泡等问题不一定触发故障码；客户希望一次反馈被持续处理，不必跨部门重复说明。

| 编号 | 页内功能 D |
|---|---|
| F06.1 | 多入口统一登记体验反馈，保留客户原始描述与附件引用 |
| F06.2 | 记录点位、设备、饮品、发生时间和现象，不强制具备故障码 |
| F06.3 | 分配持续责任人，关联可获得的原料、清洁、参数与服务变更记录 |
| F06.4 | 记录判断、处置、转协作及恢复情况，关联 F08 持续问题 |
| F06.5 | 回访体验是否改善，保留未改善或再次发生的记录 |

**状态：** 新反馈/处理中/待回访/已改善/未改善。**输出：** 从原始反馈到回访结果的连续记录。**边界：** 无故障码不能自动驳回；出品数据仅是调查线索。

**验收：** A16 无故障码也能建立有效反馈。A17 转部门后接手人可见原始描述，客户无需重填。A18 客户反馈未改善时不能以设备在线为由标记已改善。

### F07 补料协同与到点确认 · CS-07 · UI-07

**源故事 S：** 已发货或已签收不一定意味着物料可在点位使用；需明确需求、接收人和最终到点情况。

| 编号 | 页内功能 D |
|---|---|
| F07.1 | 点位物料需求台账，区分估算消耗、实际盘点与客户提出的需求 |
| F07.2 | 补料计划及人工修正，记录临时活动、人数变化和缺料原因 |
| F07.3 | 指定收货人、到点负责人、期望时间与配送引用 |
| F07.4 | 待确认、已确认、已发货、已签收、已到点分阶段跟踪 |
| F07.5 | 未到点/短缺/无人接收异常跟进，保留确认和关闭证据 |

**用户：** 补料协调、点位负责人。**输出：** 从需求到可用的交付链。**边界：** 不替代完整仓储系统；没有实盘时不显示准确库存；推算杯数不直接当成物料实耗。

**验收：** A19 物流签收后仍可处于待到点状态。A20 修改活动需求时保留修正原因和原计划。A21 页面分别标识估算量、盘点量及各自更新时间。

### F08 持续问题与服务闭环 · CS-08 · UI-08

**源故事 S：** 多次维修都结单，但客户问题未解决；需关联事件、升级统筹，并区分受理、恢复和确认。

| 编号 | 页内功能 D |
|---|---|
| F08.1 | 建立客户服务案例，关联多次报修、体验反馈和外部工单引用 |
| F08.2 | 提示可能重复事件，由责任人确认关联，保留每次事件事实 |
| F08.3 | 指定持续负责人、下一步、承诺时间与升级路径 |
| F08.4 | 分别记录受理、恢复可用、根因调查、补救/备用安排和客户确认 |
| F08.5 | 回访、重新打开、未结事项跟踪与服务事件时间线 |

**状态：** 待受理/处理中/已恢复待确认/已确认解决/重新打开。**输出：** 客户层面的完整问题解决记录。**边界：** 不覆盖工单系统原状态；备用与补偿以已确认约定为准。

**验收：** A22 三张已关闭工单仍可关联到一条未解决案例。A23 未收到确认时显示待确认，不冒充已获认可。A24 再次发生可重新打开并保留先前的恢复与确认时间。

### F09 现场责任与培训交接 · CS-09 · UI-09

**源故事 S：** 客户与服务方对日常清洁、补料、维保责任理解不同；人员变化后需要必要交接。

| 编号 | 页内功能 D |
|---|---|
| F09.1 | 按客户/点位维护双方责任矩阵及服务约定引用 |
| F09.2 | 日常任务、协作对象和适用频率配置，不套用统一行业分工 |
| F09.3 | 培训、资料送达、操作确认与有效版本记录 |
| F09.4 | 不会操作、缺用品、无人负责等障碍登记与跟进 |
| F09.5 | 联系人变化触发待交接检查，跟踪接手与培训结果 |

**状态：** 待分工/待确认/已确认/待交接；任务执行状态单独记录。**输出：** 可查的分工与现场障碍处理。**边界：** 不把未打卡直接认定为未执行或责任过失。

**验收：** A25 点位负责人能明确看到自己与服务方分别负责什么。A26 换人后形成待交接项而不自动标记培训完成。A27 缺少清洁用品能建立协作事项，不仅显示任务逾期。

### C. 费用与业务变化

### F10 费用明细与对账争议 · CS-10 · UI-10

**源故事 S：** 客户需要逐笔理解合同规则、计费期间和交付依据，确认部分与争议部分应分开处理。

| 编号 | 页内功能 D |
|---|---|
| F10.1 | 按客户、付款主体、周期查询对账单与明细 |
| F10.2 | 展示每项金额、合同规则、期间、服务/配送/变更依据 |
| F10.3 | 逐项确认或提出争议，记录原因与证据 |
| F10.4 | 跟踪争议处理、补充依据、协商调整及结果确认 |
| F10.5 | 输出对账版本与差异记录，分别汇总已确认和待解决金额 |

**状态：** 草稿/待核对/部分争议/已确认；收款状态来自独立真实记录。**输出：** 可核验的对账结果。**边界：** 不把已确认等同已付款；全部制作记录不等于计费杯数；不新增收款接口。

**验收：** A28 每项费用能追溯到明确的规则与业务依据。A29 一项争议不会掩盖其他已确认明细。A30 换机或停用的时间调整后保留原版本，不悄悄重写已确认账单。

### F11 业务变更与生效跟踪 · CS-11 · UI-11

**源故事 S：** 客户停业、缩减或迁移后，配送与计费仍按旧状态；需双方确认、生效时间和各环节执行结果。

| 编号 | 页内功能 D |
|---|---|
| F11.1 | 登记停用、恢复、数量调整、点位变化或方案调整申请 |
| F11.2 | 评估承诺、设备、物料、费用和权限的影响，标记不适用环节 |
| F11.3 | 记录内部评估和双方确认，形成原值/新值及生效时间 |
| F11.4 | 跟踪相关环节待执行、成功、失败和待人工处理结果 |
| F11.5 | 部分失败重试/补偿与最终核对，所有动作保留版本和回执 |

**状态：** 已提出/评估中/待双方确认/待生效/执行中/部分失败/已完成/已取消。**输出：** 一致、可回读的变更结果。**边界：** 不承诺跨系统天然原子；低使用不自动触发合同或配送变更。

**验收：** A31 未双方确认的申请不进入正式执行。A32 到生效时间只有部分环节成功时显示部分失败，不能显示整体完成。A33 重试不重复发货、重复调整费用或重复创建投放关系。

### F12 投放关系与历史授权 · CS-12 · UI-12

**源故事 S：** 换机退租不能使旧客户丢失应保留历史，也不能让新客户继承旧数据；共享按点位与投放有效期控制。

| 编号 | 页内功能 D |
|---|---|
| F12.1 | 记录客户、点位、设备及有效起止时间的投放关系 |
| F12.2 | 换机、移点、退租及交接登记，关联 F11 已确认变更 |
| F12.3 | 点位连续历史与设备跨投放履历分别呈现 |
| F12.4 | 显示当前共享、历史查看范围、授权依据和收回结果 |
| F12.5 | 投放区间冲突校验、结束关系回读和 A/B 客户权限核验 |

**状态：** 计划中/生效中/已结束；历史授权独立描述。**输出：** 时态投放关系和有效数据范围。**边界：** 不仅靠浏览器筛选实现隔离；迟到数据需按已定义的业务时间归属，不能默认按接收时间归属新客户。

**验收：** A34 A 退租后可按约定查看 A 租期记录，但不能看到 B 的新增记录。A35 B 接收设备后不能读取 A 的历史数据。A36 点位换机后历史连续，并能查看每台设备对应的有效区间。

**源故事 S：** 客户需要向内部说明投入效果；福利型与经营型应使用不同内容，出杯不能冒充人数或到账收入。

| 编号 | 页内功能 D |

**验收：** A37 无收款数据时报告不生成实际收入。A38 出杯数不展示为去重使用人数。A39 发布版本不含租赁商内部成本或未共享客户事项。

**源故事 S：** 到期通知可能晚于客户决策；需提前明确决策人、评估节点、顾虑和真实原因。

| 编号 | 页内功能 D |
|---|---|
| F14.1 | 续租台账：到期日、客户评估日、负责人和当前阶段 |
| F14.2 | 决策人、参与人、顾虑及信息确认状态维护 |
| F14.3 | 关联未解决问题、价值报告和改进行动 |
| F14.4 | 制定沟通、改善、方案提交和客户反馈的里程碑 |
| F14.5 | 记录已续租/未续租/待定结果及原因证据，区分已确认与推测 |

**验收：** A40 可按客户评估日而非仅合同到期日安排任务。A41 预算减少与服务不满可分别记录。A42 已续租需有结果依据，不因销售修改阶段就自动生成新合同或计费。

**源故事 S：** 高使用不一定需要加机；需要结合现场需求提出增机、移机、换型或优化现有配置。

| 编号 | 页内功能 D |

**状态：** 待核实/需求已确认/方案比较/待决策/已采纳/未采纳。**输出：** 对客户有价值的配置建议。**边界：** 不将杯量规则自动变成销售承诺；估算价值有依据和不确定性说明。

### F16 客户贡献与服务成本 · CS-16 · UI-16

**源故事 S：** 高收入客户可能有大量额外服务投入；需要区分已记录与估算成本，信息不全时不能称准确净利润。

| 编号 | 页内功能 D |
|---|---|
| F16.1 | 按客户与一致期间汇总已确认收入及可归属成本 |
| F16.2 | 分类记录耗材、维修、配送、人工等来源，分别标识已记录和估算 |
| F16.3 | 展示已知贡献、成本覆盖与未纳入项目；分摊规则和版本可追溯 |
| F16.4 | 按客户/点位查看差异，关联加急或跨区域服务等具体事件 |
| F16.5 | 记录服务优化、合作方案调整或继续投入的决策与依据 |

**验收：** A46 缺少人工或折旧等成本时显示缺口，而非声称完整净利润。A47 估算成本与已记录成本分别可见且无重复归集。A48 未获成本权限的客户经理和承租企业不能访问该页面、接口或导出。

## 5. 共享数据与横向验收

下列字段是展示与领域建模建议，不是对现有 protobuf 的已实现声明。

| 共享对象 | 最低信息 | 不可混淆 |
|---|---|---|
| CustomerRelationship | owner_tenant、customer_id、使用目的、主体角色、关联租户引用 | 客户不是隔离租户本身 |
| Site / Deployment | 点位、设备、有效区间、客户关系 | 当前归属不是全部历史归属 |
| Contact / Handover | 业务角色、范围、有效性、账号引用、交接确认 | 联系人不是全局账号 |
| Commitment | 来源、版本、确认、条件、时限、责任人 | 讨论不是正式承诺 |
| FollowUp / Case | 原事项、原因、责任人、动作、证据与确认 | 待办完成不是客户问题解决 |
| ReconciliationLine | 规则、期间、业务依据、金额、争议版本 | 对账确认不是到账 |
| BusinessChange | 原值、新值、生效、各环节执行回执 | 请求受理不是执行完成 |
| Metric / Report | 来源、范围、时间、时区、更新时间、完整性 | 零值不是缺失；估算不是事实 |

横向要求：服务端同时验证租户、客户/点位数据范围及动作权限；内部备注、金额、成本、客户共享字段分别控制。切换租户清理筛选、选择、抽屉和旧请求；迟到响应不能覆盖新上下文。创建与外部执行有幂等标识，修改有版本冲突提示。记录操作前后值、操作者、来源与回执；含个人联系方式的数据按最小可见范围呈现，设计示例不得写入真实联系方式。

查询、显示设置和业务操作分离。导出遵守当前数据权限，不能绕过字段隐藏。所有页面覆盖加载、首次无数据、筛选无结果、错误重试、无权限、未接入、延迟数据和冲突状态。真正的 0、缺失 `—`、不适用、加载中和失败分别表示。
