# 咖啡机租赁客户成功：逐页界面设计规格

- 文档编号：CS-UI-01
- 版本：v1.0 / 2026-09-09
- 关联需求：[CS-FUNCTIONAL-SPEC.md](CS-FUNCTIONAL-SPEC.md)
- 范围：16 个页面级功能各一张独立、完整的桌面界面设计图；不是 16 种风格，也不是多页拼贴。
- 定位：设计评审稿；不声称业务页面已经开发、已经接入 API 或已经通过运行验收。
- 说明：本文件是完整页面设计规格，不是图片本身。实际图稿须另行生成并检查；下列文件名是预定命名，不构成图片已入库声明。

## 1. 设计依据与统一原则

沿用用户提供的《提取设计规范.txt》：轻量企业级、数据优先、分层筛选、适度卡片化。业务列表、桌面工作台、经营统计三种模板共用视觉规范；不要把所有功能做成同一种仪表盘。

沿用 CoffeeLink 已确认布局及参考分支 `0196761678b31fa459a8a7be32938c21018f55eb` 的 `web/README.md`。这是既有方向的扩展，不重新发散三套风格。页面以租赁商客户经理的日常工作为主，同时清楚呈现承租企业共享视图的边界。

所有设计使用合成示例。不得引用真实客户姓名、联系方式、业务金额或生产性能。界面顶栏固定保留小标签“设计预览 · 示例数据”，页面数据时间清楚可见；不使用生产可用、验证通过等徽标。

## 2. 统一应用外壳

### 2.1 几何与导航

主设计画布建议为 1536×1024 横向桌面；实施时另验收 1440×900、1366×768 和 390×844。每张设计展示一个完整应用视窗，含导航、顶栏、页标题、主要动作与业务内容，不放设备模型、倾斜透视、海报边框或浏览器装饰。

一级菜单固定为工作台、设备运营、客户成功、企业中心、系统设置；当前“客户成功”有小范围浅蓝底和蓝色图标。一级导航宽度采用既有 208 CSS px（含外边距），折叠为 80px。

模块浮层保持 **480 CSS px**，与一级导航无间隙相连。浮层内部左列为子菜单，右列为快捷入口；快捷入口从上至下一行一个。子菜单全部没有箭头，选中底色仅包裹文字及图标。浮层覆盖内容，不推动主区位置或压窄主区。各主场景设计默认关闭浮层以保证业务可读性；UI-04 专门展示浮层打开状态，使既有导航规则可检查。

客户成功浮层内采用四组小标题而不是可折叠树：

| 分组 | 子菜单 |
|---|---|
| 客户关系 | 客户档案、联系人交接、服务承诺 |
| 日常服务 | 每日工作台、使用调查、体验反馈、补料协同、持续问题、现场责任 |
| 变化与费用 | 对账争议、业务变更、投放与授权 |
| 合作经营 | 价值报告、续租计划、配置机会、贡献分析 |

快捷入口按权限提供“新建客户”“登记反馈”“发起变更”“记录跟进”。没有权限不展示可执行快捷动作。

顶栏左侧为 CoffeeLink 标识、当前系统“租户运行系统”、当前租户；右侧为搜索、消息、帮助和用户菜单。主区顶部为面包屑、页面标题、必要说明和一个主按钮。客户级页面再展示当前客户/点位/周期选择，不将客户切换器冒充租户切换器。

承租企业共享视图用顶栏“承租企业视图”和授权范围说明识别；不能只换一个头像就复用租赁商全部权限。

| 用途 | 规范 |

| 主色/浅底 | #2563EB / #EFF6FF |
| 页面/工作台背景 | #F5F7FA / #EEF4FF |
| 内容表面 | #FFFFFF |
| 主/次文字 | #1F2937 / #475569 |

| 语义状态 | 成功 #15803D；警告 #B45309；错误 #B91C1C；同时有文字或图标 |

| 间距 | 4、8、12、16、20、24、32px |
| 控件/行高 | 控件 36px；标准表格行高至少 48px；紧凑模式明确启用 |

业务页使用白色连续数据面板，筛选、工具栏和表格用细线与间距区分，不给每一行工具栏套一张独立卡片。工作台可适度用浅色卡片，经营页按口径组织指标；不用大幅咖啡机照片或营销插画占据操作空间。

文本左对齐，金额/数值右对齐，状态采用轻量标签。行内常驻动作最多两个，其余使用更多菜单。图表必须有单位、范围和可解释数据状态，不放无含义装饰曲线。

### 2.3 公共交互

查询、显示设置和业务操作分离。筛选草稿与已应用状态分离；取消不能改变结果。已应用条件展示为可清除摘要。复杂表单使用 480～640px 抽屉，简单确认为对话框；打开后保持背景业务上下文、可 Esc 关闭并返回焦点。

修改关键业务前展示作用客户、点位、期间和影响。跨系统动作显示“已受理/执行中/部分失败/完成”的真实阶段；不在点击后直接显示全部成功。批量操作明确当前页与全部结果范围。正文主要字段不能用低于 12px 的字号强塞。

## 4. 逐页设计

以下布局、示例数字和状态均为设计提案。每页把核心差异画出来，不能只替换标题。

### UI-01 客户档案与全景

**角色与场景：** 租赁商客户经理查看“星桥科技（示例）”，准备一次覆盖总部和全部点位的回访。对应 F01.1～F01.5。

**画面结构：** 标题下为客户身份条，展示福利型、服务中、客户负责人、最后跟进日期。上方四项概览：12 个点位、18 台在租设备、3 个未结问题、2 项待履约；数字均为合成样例。中部为“总览 / 点位 / 合作主体 / 服务记录”页签；左侧两栏宽区域展示点位表，右侧窄栏展示总部、签约主体、付款主体关系和最近记录。

**表格：** 点位、使用负责人、投放设备、服务状态、最近事件、操作；至少展示六条可读记录。设备 SN 使用 DEMO 前缀。

**主操作：** “记录跟进”；次操作“编辑档案”。客户切换与新建档案在标题区的客户选择器提供。点位名称进入详情，主体关系可追溯。

**必须可见：** 客户和点位区别、签约和付款角色、未结问题入口；不展示虚构信用分。新增/修改用分组抽屉，重复检测只给人工建议。

### UI-02 联系人与交接

**角色与场景：** 新任行政接手旧负责人的工作。对应 F02.1～F02.5。

**画面结构：** 左主区为联系人表，筛选客户、点位、业务角色和有效状态；右侧打开交接抽屉，标题“行政负责人交接”，展示原负责人、接手人、生效日期和确认状态。

**表格：** 联系人、业务角色、负责点位、联系方式状态、交接状态、操作。使用“原行政（示例）”“新行政（示例）”等合成称谓，联系方式脱敏。

**抽屉：** 三项清单“未结服务事项”“补料与收货安排”“操作资料”，每项有待确认/已确认；下部单独显示通知更新和账号授权回收结果。底部“保存草稿”“提交交接”。

**必须可见：** 联系人退出不等于删除账号；授权回收仍有待处理时不能显示交接完全完成。背景表保留上下文，不用大面积蒙层遮到无法识别页面。

### UI-03 服务承诺与履约

**角色与场景：** 运营接手销售承诺，优先处理未兑现事项。对应 F03.1～F03.5。

**画面结构：** 紧凑的已确认承诺、待确认、逾期事项摘要；页签“全部 / 待确认 / 待履约 / 逾期”；统一筛选与表格。表格中选择一条已逾期的“点位操作培训”展示侧边详情。

**表格：** 承诺项目、客户/点位、确认状态、来源、应履约时间、负责人、履约状态、操作。未确认项用中性标签，不与逾期混淆。

**详情：** 原确认来源、适用条件、约定版本、当前动作和证据；“客户口头咨询”类记录显示草稿，不成为正式应履约事项。

**主操作：** “新增承诺”；行内“记录履约”。完成需要证据和适用的确认，不使用无依据的统一 SLA。

### UI-04 每日客户工作台

**角色与场景：** 客户经理开始一天的工作，决定先联系哪个客户。对应 F04.1～F04.5。

**画面结构：** 页面顶部日期“2026年9月9日”和范围“我的客户”。四个小指标“待跟进 / 今日到期 / 等待客户 / 已完成”。中部左侧是优先跟进队列，右侧为今日行动与待确认。队列每行显示客户、触发原因、证据时间、负责人、下一步和明确操作。

**示例事项：** 星桥科技“服务承诺今日到期”；泊岸酒店（示例）“问题恢复后待回访”；青禾连锁（示例）“对账明细有争议”。不显示无法解释的健康评分。

**特殊设计：** 此页打开客户成功模块浮层，480px 宽无缝贴合一级菜单。子菜单与快捷入口左右并排、快捷入口竖排、无子菜单箭头。浮层只覆盖左侧局部，右侧行动区依然可见，主区位置不变。

**操作：** “记录跟进”“稍后处理”“查看原因”；排除和调整优先级有原因输入。总览数字不能压过具体行动。

### UI-05 使用变化与原因调查

**角色与场景：** 某点位出杯下降，需要先调查而不是立即认定流失。对应 F05.1～F05.5。

**画面结构：** 上方客户、点位、可比周期选择和“数据完整性”说明。中部左侧较大的每日出杯趋势，横轴日期、纵轴杯数；缺失区间用断点/阴影而非补零。图表下方是营业日、搬迁或设备可用背景事件。右侧为调查卡。

**调查卡：** 状态“调查中”，初步假设“办公区搬迁待核实”，负责人、联系记录、下一步“确认恢复办公日期”；已确认原因与假设严格分栏。

**主操作：** “记录调查”；辅操作“补充背景”。下部行动记录列表有处置、责任人和复盘时间。

**必须可见：** “数据缺失 1 天”样例提示与“暂不认定流失”；趋势不能用红色直接宣判客户价值下降。

### UI-06 体验反馈与回访

**角色与场景：** 客户反馈拿铁奶泡不稳定，设备没有故障码。对应 F06.1～F06.5。

**画面结构：** 案例标题“拿铁奶泡不稳定”，状态“待回访”。左区按时间展示原始反馈、调查与处理；中区/下区是饮品、发生时间、设备、原料/清洁/参数记录入口；右区是持续负责人和回访表单。

**原始反馈：** 简洁引用“最近两次使用奶泡不稳定”（模拟文本），附“无设备故障码”中性标签。处理记录示例为“已完成现场检查，等待体验确认”，不宣称根因已证实。

**回访：** 体验已改善/未改善/暂无法确认，说明及下一步；主按钮“提交回访”。

**必须可见：** 一次反馈多部门协作的完整记录；无故障码不等于无问题；未改善可转持续问题而不要求客户重新填写。

### UI-07 补料协同与到点确认

**角色与场景：** 物料已签收却还在收发室。对应 F07.1～F07.5。

**画面结构：** 筛选客户、点位、预计到点日与进度；表格展示多个点位的咖啡豆、杯具、清洁用品需求。选中一项打开右侧交付进度，明确五阶段“待确认 / 已确认 / 已发货 / 已签收 / 已到点”。

**表格：** 点位、物料、需求数量、需求依据、接收人、到点时间、状态、操作。需求依据标签区分“人工盘点”“客户提出”“估算”。

**详情：** 当前“已签收 · 未到点”，提示“已到收发室，待点位负责人领取”；下方接收人与到点负责人分开。主操作“确认到点”，次操作“登记异常”。

**必须可见：** 物流签收和点位可用两个不同状态；没有盘点不展示所谓准确库存；不出现与本需求无关的采购审批或仓库大屏。

### UI-08 持续问题与服务闭环

**角色与场景：** 同一客户多次维修结单，但重复问题仍未解决。对应 F08.1～F08.5。

**画面结构：** 标题为“点位重复出品中断”，状态“已恢复 · 待客户确认”。顶部事实摘要为关联工单 3、当前责任人、下一次回访。左侧关联事件表，中间服务案例时间线，右侧持续行动面板。

**关联工单：** 每张单独显示已结单及实际时间；案例自身保持待确认。时间线分别标示受理、现场处理、恢复可用和等待确认。

**行动面板：** 根因调查、补救安排和待办；备用机只显示“待核对约定”或已有明确依据，不默认所有客户免费提供。

**主操作：** “记录服务进展”；次操作“发起回访”。客户确认或再次发生作为不同操作。

**必须可见：** “工单完成 ≠ 客户问题解决”的业务区别通过实际状态表达，不做抽象口号海报。

### UI-09 现场责任与培训交接

**角色与场景：** 一个点位更换负责人，需要落实清洁和补料分工。对应 F09.1～F09.5。

**画面结构：** 顶部客户/点位与生效约定；中部主体是责任矩阵表，右侧窄栏为培训交接和待解决障碍。

**矩阵：** 事项、客户责任、租赁商责任、协作人、约定频率、当前状态。示例事项包括日常清洁、物料补充、异常反馈、定期保养；具体责任标为该客户约定，不写行业统一标准。

**右侧：** 新负责人培训“待确认”，资料已送达，障碍“清洁用品不足 · 待协调”。

**主操作：** “维护责任分工”；行内“登记障碍”“查看资料”。分工修改有版本及双方确认。

**必须可见：** 培训资料发送不等于培训完成；未打卡不直接认定客户未执行。

### UI-10 费用明细与对账争议

**角色与场景：** 承租企业财务核对一个点位的月度费用。对应 F10.1～F10.5。

**画面结构：** 顶栏明确“承租企业视图”，范围“星桥科技（示例） / 总部点位”。标题区显示期间“2026年8月”、付款主体、对账版本。三项金额：账单合计 ¥2,000、已确认 ¥1,850、争议中 ¥150，均为设计样例。

**表格：** 设备租金 ¥1,200、耗材 ¥650、临时服务 ¥150；分别显示依据、期间、数量/规则及确认状态。前两项已确认，临时服务争议中。右侧展开该争议的来源、客户问题、补充依据和沟通记录。

**主操作：** “确认无争议明细”；争议区操作“补充说明”。不展示租赁商内部成本、其他客户及利润。

**必须可见：** 合计能对上，确认不是付款。页面标记“收款状态请以实际收款记录为准”；不出现无对应能力的“立即支付”。

### UI-11 业务变更与生效跟踪

**角色与场景：** 客户临时停用一个点位，双方已确认，但部分外围环节执行失败。对应 F11.1～F11.5。

**画面结构：** 标题“总部点位暂停服务申请”，状态“部分失败”。顶部流程为申请、评估、双方确认、生效执行、核对。中部左右对比原状态/新状态；下方展示执行矩阵。

**执行矩阵：** 配送计划已暂停、服务安排已更新、费用规则待重试、设备/权限按影响评估显示不适用或待处理；不得用全绿完成条掩盖单项失败。

**侧栏：** 生效时间、双方确认记录、影响范围、最近回执。主操作“重试失败环节”，次操作“记录人工处理”。

**必须可见：** 点击重试只针对失败环节，成功项不重复执行；整体完成需要最终回读核对。无未经确认的自动锁机或催收按钮。

### UI-12 投放关系与历史授权

**角色与场景：** 客户退租，设备随后投放给另一客户；同时某点位发生换机。对应 F12.1～F12.5。

**画面结构：** 上部客户/点位/设备检索，页签“点位连续历史 / 设备投放履历”。主体是一条清晰水平日期时间线，区分前后两段投放，下面是有效区间表；右栏展示当前共享及历史查看权限。

**示例：** DEMO-CF-018 在“客户 A（示例）”的投放已结束，随后在“客户 B（示例）”生效，区间不重叠。另一个点位的旧设备和新设备通过不同投放记录衔接。

**权限面板：** A 可见本租期历史、不可见 B 新增；B 可见本租期新增、不可见 A 历史。内部管理员视图可查看授权规则，不能冒充客户实际登录后的所有数据。

**主操作：** “登记投放变更”；次操作“核验查看范围”。

**必须可见：** 结束关系不删历史；共享区间和保留依据明确。不要做成只显示设备当前所属客户的一张普通表。

### UI-13 客户价值报告

**角色与场景：** 承租企业行政准备福利预算复盘。对应 F13.1～F13.5。

**画面结构：** 顶栏明确“承租企业视图”；页面为白底报告预览，仍有完整应用外壳。标题“2026年8月咖啡服务月报”，使用目的“员工福利”。上方展示服务范围、报告周期和数据更新时间。

**主体：** 使用情况、支出说明、服务表现、待改善及下期计划四组内容。示例“8,420 杯”标为设备出杯，不转换为人数；费用只引用可获得账单；服务案例区分已确认改善和待确认。

**图表：** 仅一个按周或按点位的使用图，单位杯。图旁保留“未采集去重使用人数”“不包含营业收入”等数据边界。

**主操作：** “导出报告”；共享范围和版本清晰。内部审核和发布作为租赁商角色动作，在客户视图不出现。

**必须可见：** 不渲染成销售宣传页，不用虚构满意度百分比、员工覆盖率或 ROI 证明价值。

### UI-14 续租决策与行动计划

**角色与场景：** 合同到期前，客户已经有采购评估节点，需要提前行动。对应 F14.1～F14.5。

**画面结构：** 主区是续租客户台账，列出客户、合同到期日、客户评估日、决策参与人、顾虑、当前阶段和下一步。选中客户的右侧行动区展示决策时间线及未结问题。

**示例：** 合同到期 2026-12-31、客户评估 2026-10-15；提前节点标识比到期日期更突出。顾虑“预算调整待确认”与“服务问题已确认”分开。

**行动：** 价值复盘、问题改善、方案沟通，每项有负责人和截止日期。主操作“新增续租计划”，次操作“记录客户反馈”。

**必须可见：** 没有无依据的续租概率；没有把客户经理判断当成客户确定决定；结果需依据，不自动生成合同或收费。

### UI-15 扩点与配置优化机会

**角色与场景：** 一处点位高峰拥挤，另一处低使用，客户经理比较增机与内部调整。对应 F15.1～F15.5。

**画面结构：** 标题“总部点位配置优化”，状态“需求待核实”。上部是证据区：客户原话、点位使用、现有配置、待确认条件。中部用横向方案比较表，而不是销售漏斗大数字。

**方案表：** 维持并优化、从低使用点位移机、新增设备；列示适用条件、客户收益、所需确认、资源影响。没有真实报价时标记“待评估”，不编造精确回报。

**右侧：** 需求验证与客户沟通行动，主按钮“记录需求验证”；方案确认后才可“转业务变更”。

**必须可见：** 高杯量只是线索；移机、换型或维持现状都可以是合理结论，不用采购数量作为唯一成功指标。

### UI-16 客户贡献与服务成本

**角色与场景：** 租赁商负责人判断大客户服务投入与合作方案。对应 F16.1～F16.5。

**画面结构：** 顶栏恢复租赁商租户，页标题旁标“内部经营视图”。全局客户/期间筛选。三项核心数字：已确认收入 ¥12,400、已记录成本 ¥7,200、已知贡献 ¥5,200；同期间、示例数据。另行显示估算成本 ¥800，不混入已记录成本。

**主内容：** 左侧成本构成表和可追溯事件；右侧醒目的成本缺口面板，列“部分人工待归集”“折旧未纳入”，说明已知贡献不是净利润。下方为客户/点位对比表及经营决策记录。

**主操作：** “记录经营决策”；次操作“查看口径”。金额单元格右对齐，不用绿色利润徽章把缺口藏起来。

**必须可见：** 成本来源、已记录/估算区别、未纳入项目和分摊版本。客户共享视图不可出现该页面或其导出入口。

## 5. 所有页面的状态矩阵

| 状态 | 呈现与操作 |
|---|---|
| 加载 | 保留布局，用骨架，不先显示 0 |
| 首次无数据 | 说明缺少哪类业务记录，只有有权限时才提供创建动作 |
| 筛选无结果 | 展示当前条件并提供清空条件，不误导为租户完全没有业务 |
| 接口错误 | 说明失败范围、保留上下文、提供重试；不静默回退示例 |
| 无权限 | 明确受限原因，不把业务字段伪装成空数据；敏感字段独立受控 |
| 数据延迟 | 保留最后可用数据和截至时间，标明不是实时 |
| 未接入 | 清楚标记该能力/数据源未接入，禁用依赖该来源的判断 |
| 冲突 | 显示当前版本已变及重新读取选项，不覆盖他人修改 |
| 执行部分失败 | 按环节显示成功与失败，仅对失败环节重试或人工处理 |
| 表单错误 | 定位字段并保留已填内容；提交进行中避免重复操作 |
| 破坏性/授权操作 | 二次确认影响客户、点位、有效时间和数据范围 |

主设计图各展示一个代表性状态，不把所有错误弹窗堆在一张画面中。完成实现时必须逐页覆盖适用状态；图像生成不构成这些交互已验证的证据。

## 6. 组件与工程接入建议

沿用既有 Vue 组织：`components/layout`、`components/ui`、按功能命名的业务组件、`views`、`stores`、`services`、`router`、`types`、`styles`。该建议用于后续实现，不在本轮新建生产前端。

公共组件建议：CustomerContextBar、EvidenceReference、BusinessTimeline、StatusBadge、DataQualityNotice、AssigneeField、ActionDrawer、ConfirmationPanel、SourceLinkedTable。页面按业务分别组合，不创建一个内含所有功能与状态的巨型 CustomerSuccessView。

纯 UI 组件不依赖业务 store；页面不直接网络请求；跨页状态与页内筛选区分。后端契约尚未落地的字段先列入接口清单，不声称已经存在。生产 API 失败不回退演示数据。
