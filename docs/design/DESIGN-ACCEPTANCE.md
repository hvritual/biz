# 关键页面分层视觉、交互与可访问性验收

关联 #145。验收对象固定为 `/platform/tenants` 与 `/enterprise/members`，不借验收重做业务页面。自动检查是回归证据，不等同于 WCAG 认证或产品 Owner 的人工 UX 批准。

## 分层证据

1. **结构层**：沿用 Route/Page Contract、三层 UI 架构、Design Index。业务页不能退化成 RuntimeConsole，也不能新增平行 Shell。
2. **几何层**：1366×768、1440×900、1536×1024、390×844。桌面一级栏保持当前宽度；连接式 ModulePanel 为 480px。相同一级栏状态下菜单关闭/展开时正文 x/width 变化不超过 1px。
3. **交互层**：Scrim、Escape、焦点返回；查看成员不改变勾选；详情关闭保留筛选、滚动与选择；无结果与无可信会话明确展示。
4. **语言/主题层**：至少 zh-CN/blue 与 en-US/violet 两组矩阵。语言和主题只改变呈现，不改变路由、权限或业务对象 ID。
5. **自动可访问性层**：检查可见交互控件可访问名称、重复 ID、ARIA 引用、图片 alt、唯一 H1；原键盘 tablist/dialog 测试继续运行。扫描通过不能代替屏幕阅读器、键盘任务和业务可理解性人工评审。

## 固定证据

`web/e2e/design-acceptance.spec.ts` 固定时间为 `2026-09-16T12:00:00Z`，截图关闭动画。矩阵产生 2 页面 × 2 语言/主题组合 × 4 视口 = 16 张基础截图；导航 overlay、成员详情、无结果/权限态由交互测试覆盖。截图只进入 CI artifact，不进入产品 assets。

`web/scripts/lib/design-acceptance.mjs` 与 `web/scripts/tests/design-acceptance.test.mjs` 提供隔离的正反例门禁。合法快照必须零错误；下列反例必须命中对应非零错误而不是修改期望图绕过：

- 导航展开推动正文或改变正文宽度超过 1px；
- required region 被隐藏；
- Overlay 关闭后焦点未返回；
- Scrim 点击穿透；
- 查看成员与勾选成员耦合；
- 详情关闭丢失查询上下文；
- 页面整体水平溢出；
- 长文案发生不可接受溢出。

因此自动验收同时包含“真实页面正例”和“隔离 fixture 负例”。负例只证明门禁能识别该故障，不声称当前生产页面存在同样缺陷。

验收命令：`cd web && npm run check && npm run test:e2e`。任何 console/page error、水平页面溢出、无可访问名称、断裂 ARIA 引用、菜单推动正文、查看即勾选均为失败。`npm run check` 已包含 `test:design`，因此上述负例门禁进入真实检查集合，不用单独维护第二套执行平台。

## 证据记录要求

每次资格运行记录候选 SHA、实际用例数、失败/重试/skip、总耗时和 artifact 链接。截图证据必须关联路由、场景、视口、语言和主题。fixture 证据与真实 API/可信会话证据分栏；浏览器 fixture 不能被描述为真实服务端联调。

## 人工复核清单（必须由真实 reviewer 填写）

- [ ] 仅键盘完成：展开/关闭模块导航、筛选成员、打开/关闭详情、打开新增成员确认链。
- [ ] 焦点顺序与焦点可见性合理；Esc 和关闭后焦点回到触发点。
- [ ] zh-CN 与 en-US 在 390px、1366px、1536px 下无不可理解截断；允许表格自身有可感知横向滚动，不允许页面整体横向漂移。
- [ ] blue/violet 下状态不只依赖颜色，文本、图标与对比度可理解。
- [ ] 租户页的未登录/非平台身份没有伪造 demo 成功；成员详情“查看”和“选择”语义清晰。
- [ ] 对任务“找到成员→筛选→查看→关闭→继续原列表”和“平台身份→筛租户→生命周期动作”做可理解性检查。

人工结论要记录 reviewer、日期、候选 SHA 与失败项。没有人工签名时只能声明“自动验收完成”，不能声明“人工 UX 已批准”。
