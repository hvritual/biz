# CoffeeLink Design System Runtime：执行边界

关联：[#139 总路线](https://github.com/hvritual/biz/issues/139)、[#140 设计基线](https://github.com/hvritual/biz/issues/140)。

本文件规定设计系统的维护责任和生成边界，不复制组件 API、主题数值或业务状态机。当前视觉规范为 [CoffeeLink V1.2](COFFEELINK-BUSINESS-UI-V1.2.md)，交付流程为 [UI-DELIVERY-CHAIN](../UI-DELIVERY-CHAIN.md)。V1.1 是历史设计来源，不覆盖 V1.2 已采纳的变更。声明、源码存在、执行通过和人工验收是不同状态。

## 唯一事实源

| 事实 | 唯一维护入口 | 消费者与禁止事项 |
|---|---|---|
| 组件实现和公开 Props / Emits / Slots | `web/src/ui/base`、`web/src/ui/common`、`web/src/features` 内真实 Vue/TS | 索引从源码提取；禁止手工再维护一份可覆盖源码的 API 清单 |
| 视觉基础数值 | `web/src/styles/tokens.css` | 文档引用而非复制维护；业务页不能引入竞争颜色/几何 |
| 动态品牌调色和前端应用状态 | `web/src/ui/base/theme.ts` | 公共层只消费这一入口；租户服务端配置由 #107 负责，不另建 feature theme runtime |
| 正式页面的设计义务 | `web/ui-contracts.json` | 由既有 UI/route 检查验证；不是动态 Page DSL，也不是鉴权来源 |
| 可复用业务组件场景与范围 | `web/src/features/component-scopes.json` | 仅维护源码不能推导的场景、限制、别名和来源；不能覆盖实际 Props/路径 |
| 路由、业务面与导航位置 | `web/src/router` | 索引及合同检查定位真实路由；显示语言不决定领域、权限或身份 |
| 认证、授权、额度、支付、设备执行结果 | 既有服务端领域与可信会话 | 页面只消费；组件不能推测开通、付款或设备完成 |
| CE 完成状态 | `docs/commercial-entitlements/tasks.json` 与其回执流程 | 设计系统 Issue 完成不自动更改 CE 状态 |

组件依赖沿用 `ui/base → ui/common → features/<domain> → page composition`。AppShell 属于现有 `features/app-shell`，不另建 `src/design-system`、`components`、`views` 或多包工程。基础层不依赖业务 Store/Service。公共 presentation 可以复用，领域规则不下沉至 common。

## 索引决策

组件和 Pattern 的检索结果为可重建派生数据。#142 在 `web/.cache/design-index.json` 生成本地索引；该缓存不进入 Git、前端 bundle 或独立服务。不创建可编辑的第二份规格库。

生成命令必须确定性输出：稳定 ID/顺序、生成器版本、每个来源路径与摘要。无法提取的类型标记 `unknown` 并返回源码位置，不能由模型补全为确定事实。手工字段不得覆盖自动字段。

查询前验证源摘要。缓存过期须明确失败并提示重新生成，不能静默读取旧内容或在验证时掩盖漂移。干净环境没有缓存时，从当前源码生成，再验证确定性；存在缓存则先检测新鲜度。缓存删除只能影响检索速度，不能改变页面运行或设计义务。

## 页面与 AI 生成边界

业务任务顺序：确认目标/现有接口 → 检索索引 → 读取实际实现和用例 → 选择适用模式 → 更新最小合同差量 → 普通 Vue 组合 → 运行检查 → 浏览器/真实接口证据 → 审查与 main 回读。

优先使用已有模式、领域组件、公共组合和明确 variant。新增组件必须记录已有能力为什么不适用及真实消费者；不为凑数量创建组件。ListPage 不适用于所有工作流，复杂任务可申请新 Pattern。无结果返回 gap，不自动生成替代 Vue 的语言或运行器。

Application Agent 默认不能修改全局 Token、Shell、基础层公共 API、检查器或期望截图。需要这些变化时，作为有明确文件范围的设计系统维护任务审查。已授权的独立维护 Issue 可以修改其列明范围，但不得顺手扩展到其它领域。

## 责任与例外

| 职责 | 决策与证据 |
|---|---|
| 产品/设计 Owner | 新 Pattern、信息架构变化、交互取舍、视觉基线及继续/缩减/暂停决定 |
| 前端维护者 | 公共 API、Token 准入、依赖/上游升级、兼容迁移、索引可提取性 |
| QA / 验收者 | 复现步骤、正反例、截图与真实接口覆盖；区分自动结果和人工观察 |
| 实施 Agent | 有界实现、执行记录、局限披露；不得代填人工批准或关闭未完成验收 |

这些是职责，不是未经确认的 GitHub Assignee。具体负责人未指定时在对应 PR 写明待指定；文档基线可以交付，但新视觉基线和 #146 的扩展决定不得伪造人工批准。

例外必须包含 rule ID、精确文件/路由、原因、不适用证据、替代验证、责任角色和复核条件。安全/鉴权/真实回执不可用设计例外绕过。禁止全目录通配 ignore、无限期绕过、删除失败用例和自动批准截图。检查误报应修复检查器并保留合法/非法两类回归，不将误报转为宽泛豁免。

## 成本基线和继续条件

每个试点的 PR 记录 base/head、实际改动文件数、复用组件及新增组件、需要人工同步的事实入口、返工/审阅轮次、检查耗时、误报/漏检和测试数量。检查耗时取实际日志的起止时间，不能把整个排队时间当作代码执行时间。首次没有可比样本的指标记 `未测量`，不是 0。

#140 为文档基线任务：业务组件新增数为 0，UI 行为变化为 0；当前检查耗时与测试数量从该候选的首次 CI 取得。没有组件检索/AI 试点数据，不能声称节省了开发时间。#146 用同口径报告两个真实页面的小样本观察，不外推百分比或统计显著性。

继续扩展须有证据：历史错误夹具能被拦截；合法组合不频繁误报；改组件 API 无需人工维护多个接口副本；浏览器/真实数据边界不退化；治理开销能由实际复用或减少返工解释。收益不足时保留有效基础，缩减或暂停新增机制，不撤销安全和真实性要求。

## 风险与控制

| 风险 | 控制与责任任务 |
|---|---|
| 过度平台化 / 用 YAML 重写 Vue | 本边界；#146 价值决定；不建 DSL、Renderer、Registry 服务、向量库 |
| 元数据漂移与影子代码 | #142 自动提取、来源摘要、只读查询、确定性与过期反例 |
| 模式僵化 / 领域组件与 Token 膨胀 | #143 适用/不适用；新组件与 Token 必须有真实用例；保留有界例外 |
| 自动检查造成假安全 | #145 浏览器和人工 UX；检查能力及未覆盖项明确列出 |
| 截图组合失控 | 保留四视口；附加语言/主题按层和风险选取，不做全量乘积、不删除旧回归 |
| 国际化破版或改变金额/时间含义 | #144 长文案、占位、单位/时区和业务值不变的测试 |
| 主题预览或迟到响应跨租户污染 | #107 服务端权威、单一前端主题入口、取消预览及切换隔离 |
| 上游升级和来源许可 | 后续 #150 固定来源与受控 diff；本批不自动引入外部 UI |
| 无维护者 / 版本与文档漂移 | 上述职责、精确提交证据；后续 #151 兼容与文档审核 |

## 验收与回退

沿用 `cd web && npm ci && npm run check`。UI 变化追加 `npm run test:e2e`，必要真实 API 流程与人工视觉审核不能省略。检查必须实际命中用例，skip 要有原因。四视口与导航/详情状态按现有交付链执行。

本文件的正例：组件 API 改动只更新 Vue/TS，索引重建；错误例：在 Registry YAML 手工声明另一个 Props API，或在 feature 创建另一份主题状态，即使能编译仍属违规。

本任务回退只涉及本文件与文档链接，不回退已有工程门禁或业务。每项实现仍独立 PR、核对 exact head、验收后合入 main 并回读；Issue 存在或文档写完不是产品完成。
