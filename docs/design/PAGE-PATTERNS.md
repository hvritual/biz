# 页面模式与接入

关联 #143。模式机器定义只维护在 `web/ui-contracts.json` 的 `patterns`，由原 UI Contract 检查读取；本说明不复制 API。组件/插槽、实际使用方通过 [源码索引](DESIGN-INDEX.md) 检索。数值规范仍为 CoffeeLink V1.2，本单只标记已有结构，不改布局、颜色、字段或业务动作。

## 选择模式

| 模式 | 适用与现有实例 | 差异边界 |
|---|---|---|
| ListPage | 租户、成员、角色、审计；同一种对象集合的检索与查看 | 角色全量小集合不强加分页；查看对象不等于勾选集合；指标、工具栏、详情按实际需求增加 |
| WorkbenchPage | 平台总览、套餐治理、组织架构 | 各页声明自己的工作区，组织树不能被改成万能表格，套餐未知用量不能变成零 |
| FormPage | 企业资料、当前企业设置 | 明确作用域、分组、校验、草稿、取消和提交/读回；系统设置将具体操作委托给已有设置组件，不添加空提交面板 |
| MetricsPage | 预留；没有接入的正式消费者 | 新页面需先有指标来源和范围/时间/单位/口径/新鲜度，不能创建空看板冒充落地 |

未创建 `ListPage.vue`、万能 SmartTable、Schema Renderer 或新 Shell。现有 `PageHeading`、`SearchField`、`AppPagination`、`EmptyState`、`UiDialog` 以及领域组件已能表达这些组合；抽取仅为重复的真实交互，不为目录完整性。

## 页面义务与状态

模式的 required/optional regions 是最低设计义务。每个页面可增加自己的必需区域，不能删掉模式最低要求。例外是精确页面上的 `pattern.<模式>.<区域>`，须附原因、证据、复核条件；通配符不生效。例外不能绕过会话、权限或真实回执。

原来空合同的成员、角色、组织、套餐、资料、系统设置均按实际结构补齐。新版审计页保留 main 的服务端与 demo 分支，标记其已有查询/数据区，不恢复旧预览页面。共同标题由 `PageHeading` 自身提供标记，消费者不必复制标题结构。

以下是适用状态的责任分工，不是声明每页已完成所有业务接口：

| 状态 | 呈现/允许动作 | 不能发生 |
|---|---|---|
| loading | 保留页面身份，显示正在读取；禁止依赖未取得版本的提交 | 在读取完成前展示可写的空白事实 |
| empty / no-results | 分清当前集合为空与筛选无结果；创建取决于权限，重置只改筛选 | 将 401/403/5xx 解释为空集合 |
| error | 保留必要草稿，给出针对原操作的重试 | 隐式切换 demo 或清空失败原因 |
| unsupported | 明示契约未提供，保持可读说明 | 请求队列等同于执行完成或假保存 |
| feature-locked | 展示服务端开通状态及实际存在的申请入口 | 前端自行开通或推断付款 |
| no-permission | 隐去/禁用写操作，服务端仍校验 | 使用本地身份或第二接口绕过 |
| dirty / submitting | 草稿与服务端版本分开，提交幂等；取消恢复已保存值 | 用未保存预览污染其它租户 |
| conflict / readback-failed | 保留冲突草稿与对应幂等键，只有权威读回才能确认 | 把 PATCH 受理单独视为最终成功 |

UI 原语不调用网络、不导入业务 Store/Service；页面组合原 typed service/Store，权限和金额仍由后端决定。`states` 表达义务，不是运行时渲染语言或业务完成台账。

## 必须区分的交互

成员和租户筛选有草稿/已应用两套状态，取消草稿不触发查询；即时筛选的角色页明确为即时模式，不伪装有不存在的“应用”步骤。列显示不是筛选，不能借隐藏列改变查询数据。

查看成员保留查询、分页、滚动和勾选集合；关闭后焦点返回触发按钮。跨租户或身份切换遵循已有清理规则。导航浮层在相同一级栏状态下不挤正文；桌面业务详情允许按既定并排规则收窄正文，不把这两个几何约束混为一谈。

## 新页面接入顺序

先记录用户目标和服务端接口边界，用 `design:find` 检索真实组件/模式，再读取源码和实际消费者。选择适用模式并解释不适用项，更新现有 Router 与 `ui-contracts.json` 的最小差量，以普通 Vue props/slots 组合。可复用业务组件的非代码场景信息仍在 `component-scopes.json`。

接入 ListPage 可参考 MembersView 的 `MemberFilters → 数据区 → AppPagination`；非分页集合参考 RolesView。接入 FormPage 参考 CompanyView 的真实字段/草稿/读回分离，不能复制企业资料字段到其它领域。需要独特布局时提交有真实用例的模式缺口，经产品/设计 Owner 审查，不扩展另一份页面 DSL。

## 验证与证据

执行 `cd web && npm run design:index && npm run check && npm run test:e2e`。来源改变后显式重建派生索引，不在检查中隐藏漂移。

新增 pattern 正反例纳入原 `test:design`；覆盖缺必需区、可选区缺省、精确例外、重复区、错误实例、误用预留模式。`page-patterns.spec.ts` 在七个既有页面、四视口断言真实区域并保存28张截图。原成员查看/选择、Esc 焦点返回、租户切换、导航 overlay 和 API 失败回归继续运行。

截图与测试输出进入现有 CI artifact，不进入 assets。工程检查、自动截图复核与人工 UX 结论分别记录；人工未审核时保持对应验收项未完成。模式变更可单独回退，不能回退当前服务端审计集成或删除原检查。
