## 本分支实际实现

代码仅位于 `internal/notification/domain`，是无 I/O 的不可变目录核心，不创建第二 Executor、身份客户端、数据表或 HTTP 入口。

| 能力 | 实现 | 需求对应与边界 |
| --- | --- | --- |
| 消息级别 | urgent / important / general；固定紧急、重要、一般顺序 | FR-138～140 的内部表示；级别绝不是绕过个人偏好的依据 |
| 类型目录 | `NewMessageTypeCatalog` 接收完整、显式的子类型注册快照 | 不编造生产消息类型、模板或事件到级别的映射 |
| 筛选和总数 | `MessageTypeQuery` 组合编码、名称、级别，列表、总数及三组计数来自同一个快照 | FR-141～143 的核心逻辑；尚未接 HTTP/页面 |
| 分页 | 显式 page/page size、稳定排序、越页空结果且保留同条件总数 | 不能把类型目录分页当作 FR-144/145 的租户配置分页 |
| 渠道目录 | `NewChannelRegistry` 接收显式注册；列表包含不可配置原因 | FR-155 的内部基础，不代表渠道接口、生产注册表或实际投递已完成 |
| 渠道选择校验 | 未知、不可配置、重复代码、非法别名拒绝；失败不返回部分结果 | 不静默丢弃坏渠道后继续保存；没有默认获准渠道 |
| 隔离 | 构造时复制、结果复制、无写方法；可并发读取 | 这是目录快照隔离，不是租户数据权限验收 |

### 内部查询和注册约定

下列是本次内部代码明确采用的工程约定，不是把未决产品政策改为 ACCEPTED。后续公开 PB/API 形成时必须显式映射这些约定，不能依靠隐含转换。

1. `nil` 注册集合表示未取得目录，返回 `ErrCatalogUnavailable`；显式空切片表示已取得的合法空目录。零值和 nil 指针目录同样不可用，不把初始化/读取失败伪装为零条记录。
2. 类型及渠道编码使用 1～64 字节小写 ASCII，以字母开头，后续允许字母、数字、`.`、`_`、`-`。拒绝大小写/空格别名，不静默归一化。名称要求有效 UTF-8、非空、无首尾空白/控制字符，最多 256 Unicode 字符。
3. 类型筛选字段为 `CodeContains` / `NameContains`，按字面、区分大小写的子串匹配；与级别条件以 AND 组合。`%` 和 `_` 不具有 SQL 通配符语义。空筛选值表示不限制该字段。
4. 页码从 1 开始，page size 明确取 1～100；零、负数、超上限和无效级别均返回错误。先检查界限再计算偏移，最大整数页码不会溢出或回到第一页。
5. 类型稳定排序为级别顺序后按编码字节序；三组计数先筛选后统计、分页前计算，组数始终为三。渠道按编码排序。
6. 渠道 `configurable` 只表示目录元数据允许被配置；不表示供应商健康、用户同意、发送成功或消息已送达。不可配置项必须附非空原因。
7. 空渠道选择只在目录解析层视为合法空集合，不在此决定配置的最少渠道数/接收人数；这些约束必须来自批准的配置合同。新配置、编辑及投递必须读取当前目录，不能把持有旧快照当作持续放行资格。

## 明确未实现的部分

- 生产子类型清单、渠道清单、来源加载器与目录不可用的 HTTP/UI 表达。
- Notification PB / 生成 Action / Application / root UoW / runtime 接线。
- tenant + group + level 配置及接收人持久化、多级别创建整体事务、CAS/幂等、审计、编辑集合替换和无孤儿删除。
- 当前企业、当前用户可管理分组的过滤；同条件总数、接收人筛选；A/B 企业与其他用户的反例。
- 第一/第二联系人及其他接收人的可信候选目录适配。
- canonical 类型/配置页面、创建/编辑/删除表单和四视口真实用户旅程。
- #185 的 outbox、投递、供应商回执，以及必要安全消息的政策例外。

所以 `go test` 通过至多证明内部目录性质，不能勾选 #184 的五项业务验收，也不能报告“消息配置已可用”。
