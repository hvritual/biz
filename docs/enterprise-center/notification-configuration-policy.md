# 企业消息配置一期执行合同

关联 #184、#167、#185。来源：2026-09-25 用户明确指令“所有待决策项采用建议，然后完成企业消息功能”。此前部分问题只有问题没有建议值；本文明确区分本轮委托下补齐的实施参数，不伪造先前逐项签字。

## 已采用规则

- 注册 `in_app`（站内）、`sms`（短信）、`email`（邮件）。注册不代表投递就绪；不可配置项必须带原因，写入重新校验。#184 的站内项表示配置能力，不表示 #185/#186 的送达或收件箱已验收。SMS/email 在适配器未接通时不可新选，不提供假成功开关。
- 可选短信/邮件服从当前个人偏好；紧急、重要不是安全消息豁免。既有验证码/账号恢复等受控身份流程独立，不接受普通调用者标记任意内容为安全消息。
- 第一联系人必填；第二联系人选填且不同人。附加接收人最多100名，去重不是静默行为：重复、与前两者重合、越租户、停用或已移除成员均拒绝。
- 候选来自 Access 的当前有效 Membership 和 User；仅返回身份ID/显示名，不返回明文手机号、邮箱、密码或令牌。通知域不直接读取Access/Profile表。
- 消息分组一期为资源域的当前租户点位。配置目录和动作的可管理范围消费当前 Access 动作权限角色策略约束、成员显式点位范围和资源域当前存在性；部门/负责人/前端传入身份均不产生权限。
- tenant+group+level 唯一。一次选多个等级按等级生成记录，所有写入、关系、幂等回执、审计全部成功或全部回滚。编辑不允许修改tenant/group/level身份，关系集合整体替换；删除关系与配置同事务。
- 每个配置独立版本；更新/删除必须CAS。幂等键与可信tenant、actor、操作绑定；原键变更请求拒绝，重放不覆盖新状态。业务成功需要服务端回执和权威回读。
- 列表采用同一快照、相同过滤的总数与分页；缺目录/鉴权失败不转成成功空表。错误区分无会话、无权、越界对象、重复组合、版本冲突、渠道不可用和服务异常。

## 界面与验收

沿用canonical系统设置通知入口及现有Shell/ListPage/表单/对话框，增加类型目录与配置列表，不复制个人中心。当前企业、对象、作用范围、可执行动作、回执和恢复路径可见。四视口为1366×768、1440×900、1536×1024、390×844，补充键盘与取消确认。

本合同只解决消息配置相关产品决策；不把#167全部待决、生产供应商配置、密钥托管或真实验收签字标为完成。#185负责真实路由/耐久投递/失败终态，#186负责未读入口。源码测试完成、main合并、实际部署分开记录。
