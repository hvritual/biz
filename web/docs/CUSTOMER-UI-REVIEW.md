# CoffeeLink 客户经营界面审核

## 基线与交付边界

- 指定基线：`build/coffeelink-visual-verify` / `911ab19122ec009de8028fdc4b293b1358127be1`。
- 依据：用户提供的《业务界面设计规范 V1.1》及 CoffeeLink 客户经营细节 V2 的 38 个独立页面/状态。
- 本次交付：原 Vue 工程中的原生组件、路由、表单、列表、看板、日历与可操作的本地预览闭环，不是将设计图片贴进页面。
- 审核入口：运行 `web` 后访问 `/#/customers`；企业中心原入口保持不变。
- 未接入客户经营生产 API、真实身份鉴权、财务核销、合同生效、设备操作、短信/邮件/企业微信发送或服务端 SLA 时钟。页面中的专业业务来源是明确标注的示例只读投影，操作回执只表示本地预览状态已保存。
- 共享客户视图用于检查字段投影和确认/退回交互，不是可对外发布的安全客户门户。不能把前端隔离与权限示意等同于后端安全边界。

## 复用与组织

复用原 `AppShell`、`AppHeader`、`PrimaryNavigation`、`PageHeading`、`MetricCard`、`UiDialog`、`StatusBadge`、`AvatarMark`、`AppPagination`、`EmptyState`、`AppIcon` 等，不修改这些组件及原 `tokens.css` / `base.css`。`ModulePanel` 只扩展客户域数据映射，客户经营使用既有一级菜单入口，未创建第二套侧栏。

- `src/views/customer/`：路由页面与页面级查询/选择状态。
- `src/components/customer/`：事项视图、业务详情、证据选择与领域动作表单。
- `src/services/customer/`：类型化规则、命令、来源投影、规则评估、导入校验和持久化边界。
- `src/stores/customer.ts`：租户隔离的本地状态、版本冲突、草稿、操作幂等与回读。
- `src/router/customerRoutes.ts` / `customerNavigation.ts`：懒加载路由、原 Shell 的菜单和快捷操作配置。
- `src/styles/customer.css`：以现有公共变量表达客户页面样式，不重写全局导航尺寸。

明确保留基线的主题尺寸：一级栏 192/64px、顶栏 64px、连接式浮层 480px。V1.1 的 200/68/56px 是默认建议；本任务要求优先复用分支既有布局。导航展开不改变正文位置和宽度，导航与业务详情仍分开管理。

## 验证方式

```bash
cd web
npm ci
npm run check
npm run test:e2e
npm run dev
# 浏览器打开 http://localhost:5173/#/customers
```

`check` 包括类型、lint、架构边界、单元测试与生产构建。Playwright 在 GitHub 云端 Chromium 执行，保留既有企业中心/侧边栏回归，并逐个运行 38 页对应交互与异常路径。源码清单记录公共组件还原前后 SHA256，截图来自实际 `vite preview` 运行页面。

运行日志、最终通过数量、对应 run ID 和截图 SHA256 随本次审核附件交付，以最终云端回读结果为准。本文件不将尚未运行的测试提前写为通过，也不代表用户已批准视觉稿。

## 有意差异与后续接入边界

1. 导航与全局尺寸以指定分支组件为准，不为贴合图片重建 Shell。
2. 客户/金额/编号/日期采用相互一致的示例；展示缺失来源时使用 `—` 与说明，不显示其他客户的数据。
3. 同一源数据驱动多个状态：通过真实预览操作进入成功、失败、复验及重新打开，而非把独立设计图数据直接混合。
4. 业务来源与客户端可见性均是本地演示契约；真实权限、合同、应收、运维、投放、通知、后台计时仍需按项目接口独立接入。
5. 不合并 `main`，不修改指定原分支；最终原生源码分支供本轮审核与后续迭代。
