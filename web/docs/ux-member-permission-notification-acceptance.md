# 成员、权限与通知 UX 验收方案

状态：待真人可用性测试。本文不把自动化检查或预览数据当成用户研究结果。

## 目标与边界

目标用户是企业所有者、HR/行政和业务主管。操作应在当前列表或编辑面板完成，避免为了高频任务跳到另一层页面。所有写入仍以服务端会话、权限、幂等键、版本校验和读回为准；前端不能把无权操作显示为成功。

当前界面已提供成员列表内的新增/邀请、批量启停、详情抽屉、角色复制、分组权限全选、变更前校验和通知偏好确认。真实 API 目前**没有管理员密码重置命令**，通知偏好契约目前只有当前企业的可选短信/邮件开关。因此密码重置、通知类型订阅和接收频率不能用纯前端伪造为“已上线”。

## 核心任务收敛到三步

| 任务 | 入口 | 三步路径 | 必须的前置反馈 |
| --- | --- | --- | --- |
| 新增/邀请成员 | 成员列表的“新增成员”或“邀请成员” | 1. 填身份和联系方式；2. 选组织、角色与激活方式；3. 创建并读回结果 | 即时校验账号、联系方式、激活方式和额度；明确链接/短信的下一步与有效期 |
| 编辑/调整成员权限 | 成员行“编辑”或“更多 → 变更角色” | 1. 打开当前成员；2. 勾选角色/范围并查看变更前后；3. 保存并读回 | 最后所有者、失效角色、版本冲突均在提交前阻断 |
| 移除成员 | 成员行“更多 → 移除并交接” | 1. 选择移除；2. 填原因并确认影响；3. 完成后显示回收站入口 | 明示角色、数据访问和会话影响；最后所有者必须先交接 |
| 批量启停 | 列表勾选后的工具栏 | 1. 勾选同状态成员；2. 填原因并确认；3. 提交并刷新当前页 | 不允许混合状态、重复选择或触及最后所有者；失败对象要逐个指出 |
| 新建/编辑角色 | 角色列表的“新建角色”或行内“编辑” | 1. 填角色和数据范围；2. 在权限矩阵中选择；3. 保存并读回 | 分组计数、全选/半选状态、变更后的可用权限目录与保存前复核 |
| 复制角色 | 角色行内“复制” | 1. 点击复制；2. 改名称并确认权限/范围；3. 保存并读回 | 内置角色只允许复制为自定义角色；不可把复制误解为直接授予成员 |

权限项没有天然顺序，拖拽会引入误操作且不利于键盘用户。因此此处用“分组矩阵 + 全选/半选 + 分组快捷定位 + 已选计数”替代装饰性的拖拽。若未来出现“优先级排序”这一真正有序的业务概念，拖拽必须有键盘等效操作、放置提示和撤销。

## 界面与交互准则

- 高频入口：新增、邀请、批量启停、导出保留在成员列表工具栏；查看、编辑和更多操作保留在对应行，避免层层跳转。
- 批量操作：只对当前筛选页的显式选择生效；工具栏持续展示选择数，确认弹窗列出目标姓名、原因、影响和不可操作原因。
- 权限配置：按业务域分组；组头显示 `已选/总数`，全选框应支持半选；每个权限项同时提供人能理解的名称和最小范围说明。保存前重新读取权限目录，避免陈旧权限被写入。
- 复制：当前已经支持“复制角色”。“复制成员权限”应作为后续 API 能力：选择来源成员和目标成员后，只复制角色绑定，不复制个人资料、登录状态、MFA、业务范围或安全凭据；提交前显示来源、目标、将增加/移除的角色与最后所有者保护。
- 反馈：写入中使用明确进行态；成功只在服务端读回后显示；不确定结果只提供“核对本次修改”，不能鼓励重复提交。

## 密码重置：信息触达文案与状态

管理员密码重置在真实服务接入前应保持不可用并解释原因；预览模式的提示也不得暗示真实邮件或短信已发送。服务端提供命令后，采用以下触达链路：

| 节点 | 用户可见文案 | 用户下一步 |
| --- | --- | --- |
| 触发前 | `向 {姓名} 发送重设密码链接。链接将在 {时长} 后失效；为保护账号，不会显示或发送旧密码。` | 核对收件邮箱/手机号，填写原因并确认 |
| 提交中 | `正在安全地创建重设链接…` | 保持当前页，避免重复点击 |
| 已受理、待投递 | `请求已受理。我们正在向 {脱敏地址} 发送链接；请勿重复提交。` | 允许查看投递状态 |
| 投递成功 | `重设链接已发送至 {脱敏地址}，将在 {时长} 后失效。若不是本人操作，请立即联系管理员。` | 提供“返回成员列表” |
| 链接过期/失败 | `该链接已失效或未能送达。请重新发起一次，不要转发链接或验证码。` | 一键重新发起，保留操作原因 |

安全底线：只显示脱敏地址；不回显口令或验证码；有速率限制和原因审计；密码或会话变化后说明哪些会话将失效。

## 通知：渠道、层级与克制原则

| 优先级 | 示例 | 默认渠道 | 文案应包含 |
| --- | --- | --- | --- |
| 紧急/安全 | 密码重置、异常登录、权限被移除 | 站内 + 邮件；短信仅在绑定且策略允许时 | 发生了什么、影响、时效、唯一入口、反钓鱼提示 |
| 重要需处理 | 邀请待激活、审批、角色变更待确认 | 站内 + 邮件 | 背景、要完成的动作、截止时间、直接入口 |
| 常规 | 报表、订阅事项、一般更新 | 站内为主，可选邮件摘要 | 背景、是否需要动作、摘要频率和退订入口 |

个人偏好应按“通知类型 × 渠道 × 频率”表达：安全类不可关闭；重要类可选即时或每日摘要；常规类可选即时、每日摘要、每周摘要或关闭。每次修改都要标示作用企业、作用账号、是否为可选通知，并在读回确认后提示成功。当前实现仅有可选短信/邮件开关；类型和频率必须待后端契约、投递策略及审计能力就绪后启用。

统一通知句式：`因为{背景}，请在{时效}前{动作}。` + `入口：{可见动作}`。不以“系统异常”“操作失败”等技术术语替代用户可执行的信息。

## 可用性测试与验收记录

### 受试者与任务

招募 20 人：企业所有者 5、HR/行政 5、业务主管 5、首次使用的受权管理员 5。每人使用独立测试租户并完成：邀请成员、编辑成员角色、批量停用并复原、新建或复制角色、发起密码重置、调整通知偏好、从一条通知找到并完成目标动作。任务顺序应轮换，避免学习效应。

记录每项任务的开始/结束时间、完成/放弃、误操作、是否需要协助、SUS 或 5 分满意度、对密码重置说明的复述、对通知背景/动作/时效/入口四项的提取。不得用员工姓名、手机号、真实验证码或生产通知进行测试。

### 判定规则

- 核心成员/权限任务成功率：20/20（100%）。
- 与改版前同一任务基线相比，完成时间中位数至少降低 40%；计算式为 `(基线中位数 - 改版中位数) / 基线中位数`。
- 密码重置流程理解：20/20 能正确说出收件对象、有效期、下一步和“不要转发链接/验证码”。
- 通知核心信息获取：四项提取正确数 / 总项数不低于 95%。
- 过度打扰：记录每人对同一事件收到的渠道数；安全事件允许多渠道，普通事件不得因同一事件重复打扰。

### 当前证据与缺口

- 已通过静态门禁和 315 项单元测试，覆盖成员批量状态保护、最后所有者保护、通知偏好读回/冲突恢复、个人安全验证等逻辑。
- 成员端到端用例已定义批量启停、详情焦点回归、租户切换和移动端无横向溢出；本机无法运行，因为 Playwright Chromium 不支持当前 macOS 版本且没有可用系统浏览器。产品设计浏览器连接同样没有可用实例，因此本轮没有把历史截图作为审计证据。
- 因此本文件中的体验指标尚无真人结果，不能声称“效率提升 40%”“成功率 100%”或“理解率 100%”。完成 20 人测试并记录原始数据后，才可填报这些结论。
